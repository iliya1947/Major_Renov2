## 1. Главное заключение

**Два независимо установленных случая старого проектного контекста ещё встречаются в датированном вторичном снимке model-visible Memory от 12 октября**, через **5+ суток** после появления более правильного primary source:

- **P1 / PR #184:** первоначально ошибочное `«служебные PR удалены; обсуждение — в implementation PR»` сохранялось в snapshot минимум **5 суток 8 часов 1 минуту после merge** корректного process-regulation PR #184 (или **5 суток 11 часов 25 минут** после самостоятельной коррекции ассистента, если пользоваться приблизительно восстановленным временем 6.10 10:39 UTC).
- **P2 / PR #181:** прежний статус `hold/not merged` сохранялся минимум **5 суток 4 часа 10 минут после фактического merge** PR #181. Это stale-state, а не второй случай corrected-model-error persistence.

**Ни для P1, ни для P2 нет подтверждённого model-visible *updated replacement of the same item* в последующем датированном snapshot**. Поэтому **upper bound момента обновления нельзя установить**, а проверяемый период staleness нельзя автоматически продлить на 13–16 октября.

**Текущий model-visible контекст 17 октября содержит новые process/role факты**, но не является полным платформенным экспортом памяти и **не показывает, что exact old items когда-либо были удалены из backend**. Нельзя смешивать `item отсутствует в текущей выжимке` с `система удалила этот item`.

## 4. Связь с ошибками GPT-6 12–16 октября: temporal opportunity ≠ доказанное сопадение в момент ответа

**Сам snapshot по local time — начало 12.10 (01:04 Jerusalem).** Это первый день указанного Sol интервала 12–16. Следовательно, существование старых пунктов в **некотором модельно-видимом представлении в этом broad calendar window** подтверждено.

Релевантные **поздние проблемные эпизоды** из исследованной истории:
- **12.10:** GPT-6 после чтения `AGENTS.md` продолжила план, созданный **до** прочтения; ошибочная role/workflow transition. Позднее регламент #218 лишь закрепился, точный контекст каждого GPT-6 хода в M5 не доступен. Похож на риск P1, но старый план в *том же чате* — явная конкурентная причина.
- **14–15.10:** широкую задачу по аудиту тестов GPT-6 неверно сузила до Editor PR #215, затем пользователь исправил. Этот PR #215 **отсутствует в 12.10 Memory snapshot**; P1/P2 не являются специфическим объяснением.
- **15–16.10:** Editor 2.0 и дальнейшие role/handoff confusion. Ошибки с PR/ролями **похожи по семантике** на P1, но старую историю `no service PR` как их контекст не установили; пользователи/файлы/PR могли дать такую же информацию. P2 `#181 hold` в проверенных ошибках не фигурирует.

**Чего мы действительно можем заключить:** устаревший project/process-контент подтверждён в снимке **в календарном интервале 12–16 октября**. Это создаёт **слабую временную возможность**, что контекст мог быть доступен модели тогда. Но нет model-visible Memory snapshot **на момент ни одного конкретного более позднего ошибочного хода**, так что **temporal overlap item + GPT-6 error НЕ ДОКАЗАН** (кроме broad date/window observation). Не заявлять `Memory caused err`, `Memory contributed`, `GPT-6 read stale item`.

## 6. Что это добавляет к M1–M4, а чего не добавляет

**Новое и установлено:** не просто `old item exists`, а **минимальная документируемая длительность** его существования *после изменения source-of-truth*: >5 суток **для двух независимых project/process items**. Это создаёт конкретное **exposure opportunity window before 12 Oct snapshot**, и подтверждает присутствие старого материала внутри широкого периода, когда встречались ошибки GPT-6.

**Не установлено:** когда произошло фактическое обновление Memory (если вообще произошло), сколько раз старые пункты выбирались для модельного контекста, какой именно полный набор старого и нового текста получила GPT-6 в моменты ошибок, роль Memory в конкретном отклонении, доля наблюдаемых ошибок GPT-6, объясняемых Memory, и какой тип данных обновляется быстрее.

**Критический отрицательный итог:** несмотря на current visible обновлённые role/workflow факты, у нас **нет upper bound для P1/P2** и **нет доказанного simultaneous stale-memory retrieval + downstream GPT-6 failure**. Результат M5 — **documented lag lower bounds + opportunity at observed snapshot, not causal attribution**.
