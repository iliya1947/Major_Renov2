# Part A — Intervention complexity is not binary

## 1. “Complex intervention” is not a yes/no property

### Established finding
**Confidence: HIGH**

Cochrane recommends thinking in terms of **intervention complexity**, not separating interventions into:
- simple;
- complex.

Relevant dimensions include:

1. number of components;
2. interactions among components;
3. interactions between intervention and context;
4. adaptation;
5. implementation variability;
6. wider-system effects.

Project consequence:
a resistance-training program can be “complex” for a review even if its exercise list is short, if outcomes depend on:
- progression;
- adherence;
- coaching;
- context;
- interaction between components.

---

## 2. Complexity matters only when it changes the question or interpretation

### Established finding
**Confidence: HIGH**

Cochrane warns against making the review itself unnecessarily complicated.

Project rule:

Do not build a full logic model merely because an intervention has many details.

Use one when the model helps resolve a real uncertainty such as:
- which components matter;
- why effects differ by context;
- why implementation succeeds/fails;
- which outcomes are proximal vs distal;
- whether combining studies is scientifically coherent.

---

# Part B — Logic model / programme theory

## 3. Logic model represents how intervention is expected to lead to outcomes

### Established finding
**Confidence: HIGH**

Cochrane describes logic models as graphical representations of theories about:
- intervention components;
- mechanisms/pathways;
- outputs;
- outcomes;
- interactions with context.

MRC's 2021 framework uses **programme theory** for the explanation of:
- how an intervention is expected to produce effects;
- under what conditions;
- how components interact;
- what contextual features influence mechanisms.

Project consequence:
logic model = structured hypothesis about the causal/implementation pathway, not a decorative diagram.

---

## 4. Programme theory should be explicit before evaluation when complexity matters

### Established finding
**Confidence: HIGH**

MRC 2021 recommends developing/refining programme theory early and revisiting it across phases.

Cochrane similarly recommends stating how the intervention is expected to work when complexity is relevant.

Project rule:
before a complex intervention-effect review, document at least a minimal theory of:

1. intervention inputs/components;
2. intended actions;
3. mechanisms;
4. implementation/process;
5. proximal outcomes;
6. intermediate outcomes;
7. distal outcomes;
8. context;
9. plausible unintended outcomes.

---

# Part C — Logic model refines the question

## 5. Logic model can expose hidden subquestions

### Established finding
**Confidence: HIGH**

Cochrane Chapter 17 lists complexity questions such as:

- under what circumstances does it work?
- which components matter?
- how do components interact?
- what mechanisms produce effects?
- what affects implementation?
- is it feasible/acceptable in different contexts?
- how does the wider system respond?

Project consequence:
a vague question:
> Does Program A work?

may actually contain several distinct evidence questions:

1. effect;
2. mechanism;
3. implementation;
4. context/moderation;
5. acceptability/feasibility.

Those may require different designs/evidence streams.

---

## 6. Logic model does not mean every node becomes a review question

### Established finding
**Confidence: HIGH**

Cochrane explicitly warns that not every aspect of complexity should be placed in the review question.

Some details can remain in:
- logic model;
- subgroup plan;
- synthesis structure;
- interpretation.

Project rule:
promote a model element into the explicit review question only if:

1. it could change the decision;
2. evidence can reasonably address it;
3. it changes eligibility/grouping/synthesis;
4. it is a key uncertainty rather than background detail.

---

# Part D — Lumping vs splitting

## 7. Logic models help decide whether interventions can be combined

### Established finding
**Confidence: HIGH**

If interventions share:
- core function;
- mechanism;
- intended outcome pathway,

they may sometimes be grouped despite surface differences.

If they differ in:
- essential component;
- mechanism;
- implementation pathway;
- context interaction,

pooling them may obscure meaningful differences.

Project rule:
lumping/splitting must follow the **causal/functional model**, not merely exercise names or program labels.

---

## 8. Form and function should be distinguished

### Project inference grounded in complexity guidance
**Confidence: HIGH/MODERATE**

Different intervention forms can serve the same function.

Example:
two progression systems may use different operational rules but both function to:
- maintain high effort;
- increase stimulus over time.

Conversely, two programs both labeled “resistance training” can have different functions/mechanisms.

Project consequence:
future program taxonomy should capture:
- **form** — what is done;
- **function** — what process it is intended to produce.

---

# Part E — Context and implementation

## 9. Context is part of the causal system

### Established finding
**Confidence: HIGH**

MRC and Cochrane both emphasize that context can:
- modify intervention delivery;
- modify mechanisms;
- modify effects;
- itself change in response to intervention.

Project consequence:
context is not merely a study-location descriptor.

Possible fitness contexts:
- supervised lab;
- commercial gym;
- unsupervised home training;
- coach-mediated training;
- limited-equipment setting.

---

## 10. Implementation can alter the realized intervention

### Established finding
**Confidence: HIGH**

An intervention as designed and an intervention as delivered are not always the same.

Relevant implementation variables may include:
- fidelity;
- dose delivered;
- dose received;
- adaptation;
- acceptability;
- adherence;
- provider behavior.

Project consequence:
if outcomes are poor, ask whether:
1. intervention theory failed;
2. implementation failed;
3. both.

---

# Part F — Theory failure vs implementation failure

## 11. Logic models help distinguish two failure modes

### Established finding
**Confidence: HIGH**

### Theory failure
Intervention was delivered as intended, but expected mechanism/outcome pathway did not produce the desired effect.

### Implementation failure
Intended intervention/mechanism was not actually delivered/received/activated.

Project training example:

Program prescribed:
- 3 hard sets near failure.

Observed:
- participants routinely stop at 8+ RIR.

Lack of hypertrophy cannot be interpreted simply as:
> “three hard sets are ineffective”

because the intended exposure was not implemented.

---

## 12. This distinction links directly to estimands and adherence

PASS-04 already separated:
- assignment effect;
- hypothetical full-adherence effect;
- completer contrast.

Logic model adds:
- **why** deviations matter mechanistically;
- which implementation variables are required to activate the intended treatment function.

Project consequence:
adherence is not only attendance.
It may need to include fidelity to critical intervention functions.

---

# Part G — Proximal, intermediate and distal outcomes

## 13. Logic models can organize outcome hierarchy

### Established finding
**Confidence: HIGH**

Cochrane logic models can show:
- proximal outputs/outcomes;
- intermediate outcomes;
- distal outcomes.

Project consequence:
this helps avoid two errors:

1. treating an early mediator as if it were the final target;
2. ignoring an early process measure that helps explain failure.

Example:

training stimulus
→ acute fatigue/effort exposure
→ repeated adaptation signal
→ muscle adaptation
→ strength/performance

These nodes are not automatically interchangeable outcomes.

---

## 14. Plausible intermediate outcome is not automatically decision-critical

### Established finding
**Confidence: HIGH**

Cochrane warns against including every theoretically plausible outcome.

Project rule:
logic model may contain many nodes, but critical outcome selection still follows PASS-03:
- decision importance;
- benefits;
- harms;
- burden.

A mechanism node remains mechanistic unless separately validated as a useful surrogate.

---

# Part H — Key uncertainties should drive questions

## 15. MRC 2021 centers key uncertainties

### Established finding
**Confidence: HIGH**

MRC's six core elements include:

1. context;
2. programme theory;
3. stakeholders;
4. key uncertainties;
5. intervention refinement;
6. economic considerations.

The framework explicitly states that programme theory and stakeholder knowledge should help identify the **key uncertainties**, which then frame research questions.

Project consequence:
do not ask every possible question implied by the model.

Prioritize:
> What uncertainty, if resolved, would most change the intervention, evaluation or decision?

---

# Part I — Different nodes may require different evidence streams

## 16. One complex intervention may require multiple question types

### Established finding
**Confidence: HIGH**

Cochrane notes that questions about:
- effects;
- mechanisms;
- implementation;
- context
may require different study designs.

Project router:

### Effect
PICO/PICOT + estimand.

### Mechanism
MEC-Q.

### Experience/acceptability
PICo / qualitative.

### Implementation
implementation module.

### Context/effect modification
effect question + prespecified moderator/context analysis.

### Evidence landscape
PCC/scoping.

These streams can later be integrated, but are not methodologically identical.

---

# Part J — Logic model may evolve

## 17. Pre-synthesis and post-synthesis models can differ

### Established finding
**Confidence: HIGH**

Cochrane supports:
- an a priori logic model;
- refinement after evidence synthesis.

Project rule:

### Version 0
Initial theory based on existing knowledge before deep synthesis.

### Version 1+
Update only when evidence changes:
- component relation;
- mechanism;
- context pathway;
- implementation assumption;
- outcome sequence.

Changes must be logged.

Do not silently redraw the model after seeing results as if it had been prespecified.

# Part K — Training-program application

## 18. Eventual training program is likely a multi-component intervention

Potential components include:

1. exercise selection;
2. loading/resistance;
3. set/repetition prescription;
4. effort target;
5. frequency;
6. progression;
7. rest;
8. feedback;
9. adherence architecture;
10. recovery/nutrition interfaces.

Not all need equal research depth.

Logic model can identify:

### Inputs
- equipment;
- time;
- baseline capacity.

### Intervention components
- exercises;
- loading/progression;
- session structure.

### Implementation
- completion;
- fidelity;
- substitutions;
- coaching/feedback.

### Mechanisms
- mechanical/neuromuscular/metabolic processes as relevant.

### Proximal outputs
- performed volume;
- effort;
- technique;
- fatigue.

### Intermediate outcomes
- adaptation;
- skill;
- tolerability.

### Distal outcomes
- strength;
- hypertrophy;
- sustained adherence;
- injury/safety outcomes.

### Context
- home environment;
- equipment constraints;
- schedule;
- behavioral conditions.

This is a future application schema only; it is not yet the final personalized program.

# Part L — When NOT to use a full logic model

## 19. Minimal theory statement may be enough

Use a short theory statement instead of a full diagram when:

1. intervention pathway is well established;
2. context/implementation are not central uncertainties;
3. only one focused causal contrast matters;
4. component interactions are irrelevant to the decision;
5. diagram adds no new grouping/eligibility/synthesis information.

Project consequence:
logic-model creation is not mandatory bureaucracy.

# Part N — Architecture decision

## 20. Logic model sits above question modules, not inside every one

Router:

### Simple focused question
→ no full logic model needed.

### Multiple components/context/mechanisms/implementation are decision-relevant
→ create logic model first.

Then route each key uncertainty into:
- effect;
- mechanism;
- qualitative;
- implementation;
- scoping;
- other appropriate module.

This prevents one giant PICO from trying to answer everything.

---

## 21. Practical rules produced by PASS-10

1. Treat intervention complexity as dimensional, not binary.
2. Use a logic model only when it clarifies a real uncertainty.
3. Logic model represents components, functions, mechanisms, implementation, context and outcome pathways.
4. Make programme theory explicit before evaluation when complexity matters.
5. Let key uncertainties—not every possible node—drive review questions.
6. Do not put every logic-model element into the formal question.
7. Use the model to guide lumping vs splitting.
8. Distinguish intervention form from function where useful.
9. Treat context as potentially causal/modifying, not merely descriptive.
10. Distinguish theory failure from implementation failure.
11. Separate proximal, intermediate and distal outcomes.
12. Do not promote mechanism nodes to critical outcomes automatically.
13. Route different uncertainties to different evidence-question modules.
14. Allow pre-synthesis and post-synthesis logic models, but version changes transparently.
15. Use a minimal theory statement when a full model adds no value.
16. Add a conditional Logic-Model Module above the final modular QUESTION_CARD router.
