# INT-04 — Reusable reasoning checklists: fast routing, deep-gate escalation, and pre-response control

Status: **CLOSED_FOR_PRACTICE v1.0 — 20/20 PASS**

Evidence cutoff: **2026-11-19**

Scope: operational compression of the canonical psychology qualification into reusable checklists for future private psychological work. No individualized psychological material is included.

## Purpose

The qualification now contains:

- Phase A methodology gates;
- Phase B domain science;
- Phase C applied/clinical/safety/ethics boundaries;
- INT-01 cross-domain contradiction and priority rules;
- INT-02 person-level evidence transfer;
- INT-03 analytic error taxonomy.

The remaining operational problem is speed and usability.

A future psychological answer should not require mechanically rerunning hundreds of questions when the task is simple.

But a short checklist must also not become a substitute for the deeper qualification.

INT-04 therefore creates a **triggered checklist architecture**:

1. one universal preflight;
2. one task-class checklist;
3. optional specialist checklists only when their trigger is present;
4. mandatory escalation to deeper canonical gates when a red flag is detected;
5. one final pre-response audit.

Canonical principle:

**Use the lightest checklist that is sufficient for the stakes and claim type, but never use a short checklist to bypass a deep gate that has been triggered.**

Never:

- checklist completed -> inference validated;
- simple task -> no purpose/privacy check;
- long checklist -> better reasoning by default;
- high stakes -> same process as casual reflection;
- low stakes -> unnecessary clinicalization;
- checklist wording -> substitute for evidence;
- one failed item -> invent an answer anyway;
- uncertainty -> fill the missing box from intuition;
- deep-gate trigger -> continue with only the short checklist;
- form compliance -> scientific validity.

# I. Question Card

## 1. Concrete dependency

INT-01, INT-02, and INT-03 are deliberately comprehensive.

Their gates contain:

- 120 cross-domain questions;
- 144 evidence-to-individual questions;
- 144 analytic-error questions.

These are appropriate for:

- audit;
- difficult cases;
- high-stakes inference;
- qualification;
- error repair.

They are inefficient as a mandatory full pass for every ordinary response.

The operational need is a compact routing layer that preserves the underlying safeguards.

## 2. Target

Create reusable checklists for:

1. rapid low-stakes reflective inference;
2. strong individualized psychological proposition;
3. causal/mechanism claim;
4. trait/state distinction;
5. measurement/score interpretation;
6. clinical/neurodevelopmental boundary;
7. relationship/social inference;
8. intervention/decision support;
9. safety/high-stakes routing;
10. private-model update;
11. correction/error repair;
12. final pre-response audit.

## 3. Required property

The checklists must be **shorter than the underlying qualification**.

They must route to, not replace:

- INT-01;
- INT-02;
- INT-03;
- relevant domain canonical blocks;
- SAF/ETH when stakes require them.

## 4. Privacy boundary

Only generic checklist architecture is stored.

Completed individualized checklists remain private.

## 5. Closure criterion

INT-04 closes only if:

- simple and complex tasks are separated;
- universal preflight exists;
- specialist triggers are explicit;
- deep-gate escalation is explicit;
- high-stakes tasks cannot remain on a lightweight path;
- person-specific conclusions route through INT-02;
- errors/corrections route through INT-03;
- cross-domain collisions route through INT-01;
- final response audit exists;
- checklists remain practical rather than encyclopedic.

# II. Operating architecture

## 6. Three-pass model

### Pass A — route

Answer:

- What kind of task is this?
- What stakes?
- Does it require individualized inference?
- Which specialist checklist is triggered?

### Pass B — reason

Use only the relevant checklist(s).

Escalate when a red flag appears.

### Pass C — output audit

Before responding:

- narrow claim;
- confidence;
- limits;
- safety/privacy;
- wording.

## 7. Default path

For a simple low-stakes psychological reflection:

**C0 Universal Preflight -> C1 Reflective Inference -> C12 Final Pre-response Audit**

## 8. Strong person-specific path

For a meaningful individualized proposition:

**C0 -> C2 Strong Individualized Proposition -> relevant specialist checklist(s) -> C12**

INT-02 becomes mandatory when C2 triggers a deep-transfer condition.

## 9. Mechanism path

For causal/mechanistic claims:

**C0 -> C3 Causal/Mechanism -> relevant domain checklist -> C12**

PSY-RES causal rules become mandatory when the claim exceeds descriptive association.

## 10. High-stakes path

For safety, diagnosis-like authority, capacity, legal/forensic/employment/custody, or other hard-to-reverse use:

**C0 -> C9 Safety/High-Stakes -> SAF/ETH deep gate -> relevant domain -> C12**

Lightweight checklists are never sufficient alone.

## 11. Model-update path

For significant private longitudinal model change:

**C0 -> C10 Private-Model Update -> INT-02 -> PRIVATE_MODEL_UPDATE_CARD v2 -> C12**

## 12. Error/correction path

When the user corrects a material premise or a reasoning error is detected:

**C0 -> C11 Correction/Error Repair -> INT-03 if material -> dependent-proposition review -> C12**

# III. C0 — Universal Preflight

Use before any substantive psychological inference.

## 13. C0 checklist

1. **Purpose** — What is the user actually asking for?
2. **Necessity** — Does this task require individualized psychological inference at all?
3. **Claim** — What is the narrowest proposition needed?
4. **Evidence** — What is directly known versus inferred?
5. **Alternatives** — Is there at least one plausible rival for a nontrivial inference?
6. **Stakes** — Is this reflective, consequential, clinical/safety, or institutional?
7. **Role** — Am I staying within psychological explanation/support rather than pretending to formal clinical/legal authority?
8. **Privacy** — Am I using only relevant private information?
9. **Freshness** — Does the task depend on mutable guidance, diagnostic standards, law, software/tool status, or recent research that must be rechecked?
10. **Routing** — Which specialist checklist is triggered?

## 14. C0 hard stops

STOP or DEFER if:

- purpose is unclear enough to change the answer materially;
- required evidence is unavailable;
- private-model information is unnecessary;
- the claim would require invented personal facts;
- legal/jurisdiction-specific action is required but not verified;
- a high-stakes task is being treated as casual reflection;
- current source/version status is required but unverified.

# V. C1 — Rapid Low-Stakes Reflective Inference

Use for:

- exploratory self-reflection;
- everyday psychological explanation;
- low-consequence pattern discussion;
- hypothesis generation.

Do not use alone for:

- formal diagnosis;
- high-stakes decision;
- strong mechanism;
- major private-model update.

## 15. C1 checklist

1. What is the direct observation?
2. What is interpretation rather than observation?
3. What is the simplest plausible explanation?
4. What is one meaningful alternative?
5. Is this state/context-specific or potentially stable?
6. Does generic science support only plausibility or something stronger?
7. What person-specific evidence exists?
8. What would contradict the preferred explanation?
9. What confidence wording fits?
10. Is the conclusion useful without freezing identity?

## 16. C1 output rule

Prefer:

- “one plausible explanation is…”;
- “this is consistent with…”;
- “the current evidence suggests…”;

when evidence does not support stronger language.

## 17. C1 escalation

Escalate to C2 if:

- proposition becomes important to the private model;
- confidence is intended to be MODERATE or higher;
- claim spans multiple contexts/times;
- user may act materially on it.

Escalate to C3 if:

- explanation becomes causal/mechanistic.

Escalate to C6/C9 if:

- clinical/safety content emerges.

---

# VI. C2 — Strong Individualized Psychological Proposition

Use when a proposition is intended to become:

- a strong working premise;
- a durable private-model proposition;
- a meaningful explanation of repeated behavior;
- a basis for consequential personal reasoning.

## 18. C2 checklist

1. Exact proposition?
2. Claim type: state / trait / capacity / preference / function / prediction / mechanism?
3. Raw provenance?
4. Is evidence direct or proxy **for this claim**?
5. Is the measurement/observation valid for this interpretation?
6. What applicable generic evidence exists?
7. Does that evidence transport to this context/person/use?
8. What repeated person-specific evidence exists?
9. Are occasions/sources genuinely independent?
10. What is the strongest plausible rival?
11. What contradicts the proposition?
12. What evidence-dependency does it have?
13. Which L0–L6 level is justified?
14. Which confidence tag is justified?
15. What would disconfirm or materially narrow it?

## 19. C2 deep-gate triggers

Run INT-02 if any is true:

- proposition is trait-like;
- proposition is mechanism-level;
- evidence streams disagree;
- model update would be structural;
- multiple downstream propositions depend on it;
- high confidence is contemplated;
- user challenges it materially;
- use stakes are S2 or above.

## 20. C2 prohibition

Do not create a strong person-specific proposition from:

- population evidence only;
- one ambiguous event;
- one unvalidated score;
- one AI-generated pattern;
- demographic/group membership alone.

---

# VII. C3 — Causal / Mechanism Claim

Use when wording includes:

- causes;
- because;
- mechanism;
- maintains;
- drives;
- leads to;
- explains why;
- intervention changes X through Y.

## 21. C3 checklist

1. Is the claim association, prediction, causal effect, or mechanism?
2. Is temporal order known?
3. Could reverse causation explain the pattern?
4. What confounders are plausible?
5. Is evidence between-person or within-person?
6. Is mediation only statistical or causally identified?
7. Has the proposed causal variable changed or been perturbed?
8. Did the predicted outcome change accordingly?
9. Is there replication/reversal or prospective evidence?
10. What rival mechanism predicts something different?
11. Does generic mechanism evidence actually transport here?
12. What is the narrowest causal statement supported?

## 22. C3 downgrade rules

If only association exists:

say association.

If prediction exists without intervention:

say prediction.

If treatment helped but active ingredient is unknown:

say outcome improvement, not mechanism proof.

If neural correlate exists:

say neural correlate/sensitivity, not psychological mechanism.

## 23. C3 deep-gate trigger

Use PSY-RES causal design rules and INT-02 when:

- mechanism is person-specific;
- causal conclusion is consequential;
- model update depends on mechanism;
- mediation/intervention/neural evidence is central.

---

# VIII. C4 — State / Trait / Time / Development

Use when the claim concerns:

- stable personality;
- repeated tendency;
- “always/usually”;
- developmental origin;
- change over time;
- persistence;
- relapse/recurrence;
- baseline versus episode.

## 24. C4 checklist

1. What is the observation window?
2. Current state or historical pattern?
3. One context or multiple relevant contexts?
4. One episode or repeated pattern?
5. Is behavior opportunity comparable?
6. Could stress, sleep, health, environment, or role change explain the difference?
7. Is a stable conditional pattern possible instead of a global trait?
8. Is developmental onset actually evidenced?
9. Is age/recognition being mistaken for cause/onset?
10. Is change larger than measurement/context noise?
11. Is stability metric specified?
12. What evidence would show the proposition is too broad?

## 25. C4 rule

**Stable does not mean fixed. Variable does not mean traitless. Developmental does not mean immutable.**

## 26. C4 escalation

Use PER/DEV/CLN/NDEV and INT-02 when:

- trait confidence is MODERATE+;
- developmental disorder is considered;
- current episode may be confused with enduring pattern;
- private-model architecture is changing.

---

# IX. C5 — Measurement / Score / Task / Biomarker Interpretation

Use when evidence includes:

- questionnaire;
- psychometric score;
- percentile;
- cutoff;
- cognitive task;
- classifier;
- AI score;
- physiological measure;
- neural measure;
- digital proxy.

## 27. C5 checklist

1. What was directly measured?
2. What construct is the measure intended to represent?
3. Is validity evidence appropriate for this use?
4. Is reliability adequate?
5. Is person-level precision known/adequate?
6. Are norms/reference population appropriate?
7. Is invariance/comparability relevant?
8. Is cutoff being treated as a natural category?
9. Is the task impure or multiply determined?
10. Is the proxy being renamed as the psychological construct?
11. Is model fit/accuracy being mistaken for construct validity?
12. Does the interpretation exceed the validated use?

## 28. C5 output rule

Name the measurement at its own level first.

Examples:

- score;
- task performance;
- classifier output;
- physiological signal;
- neural correlate.

Only then state the psychological inference it supports.

## 29. C5 deep-gate triggers

Use PSYCHOMETRICS if:

- individual score interpretation matters;
- change score matters;
- cutoff matters;
- group comparison matters;
- automated/AI scoring matters.

Use NEU when biological/neural interpretation matters.

---

# X. C6 — Clinical / Neurodevelopmental Boundary

Use when the discussion includes:

- symptoms;
- disorder label;
- diagnosis-like reasoning;
- impairment;
- developmental condition;
- differential diagnosis;
- screening result;
- formal assessment question.

## 30. C6 checklist

1. Symptom, syndrome, trait, or diagnosis?
2. Is duration/course known?
3. Is distress/impairment/context known?
4. Could normal variation explain it?
5. Could another psychological condition explain it?
6. Could developmental history change the interpretation?
7. Could medical/neurological/substance/sleep factors matter?
8. Are overlapping symptoms being double counted?
9. Is a screen/score being mistaken for diagnosis?
10. Is one salient symptom driving the whole classification?
11. Is developmental onset required and actually evidenced?
12. Is current observation being mistaken for lifelong history?
13. Would formal diagnosis require information/process unavailable here?
14. What is the narrowest non-diagnostic conclusion that remains useful?

## 31. C6 hard boundary

General-purpose conversational analysis must not present itself as:

- formal diagnosis;
- licensed clinical assessment;
- treatment order;
- medico-legal assessment.

## 32. C6 escalation

Use CLN/NDEV/SAF and real-world professional assessment when:

- formal classification matters;
- impairment/severity is consequential;
- capacity or acute risk is involved;
- developmental differential is material.

---

# XI. C7 — Relationship / Social Inference

Use when inferring:

- motive;
- empathy;
- attachment;
- conflict pattern;
- partner intent;
- validation;
- responsiveness;
- coercion;
- social influence.

## 33. C7 checklist

1. What behavior/report is directly observed?
2. Is motive being inferred from behavior?
3. Is one person's report being treated as dyadic truth?
4. Is perception being separated from objective behavior?
5. Is relationship-specific pattern being turned into global personality?
6. Is attachment level specified: state / relationship-specific / global?
7. Is validation being confused with factual agreement?
8. Is reciprocity being confused with equal responsibility?
9. Are power/coercion/safety asymmetries checked?
10. Could culture/context alter interpretation?
11. What alternative social explanation remains viable?
12. What conclusion can be made without mind-reading?

## 34. C7 priority rule

If credible coercion, violence, or acute safety is present:

route to C9/SAF.

Do not keep the analysis in symmetric communication framing.

## 35. C7 output rule

Prefer temporal/dyadic patterns over fixed partner-character labels when evidence supports process rather than trait.

---

# XII. C8 — Intervention / Behavior Change / Decision Support

Use when discussing:

- psychotherapy;
- behavior-change strategy;
- habit change;
- intervention choice;
- treatment evidence;
- decision aid;
- forecast;
- recommendation under uncertainty.

## 36. C8 checklist

1. What outcome matters?
2. Efficacy, effectiveness, implementation, or mechanism?
3. What comparator?
4. What harms/costs?
5. Is average effect being turned into individual effect?
6. Are validated moderators available?
7. Are preferences/values relevant?
8. Is feasibility/adherence relevant?
9. Is prediction being mistaken for treatment-effect estimation?
10. Is package efficacy being mistaken for active mechanism?
11. Is decision quality being confused with realized outcome?
12. Is more information actually valuable for the decision?
13. Is the choice reversible?
14. Is an AI/decision aid becoming the decision maker?

## 37. C8 rule

A useful recommendation can combine:

- population evidence;
- contraindications;
- preferences;
- feasibility;
- prior response;
- direct individual evidence.

It must not pretend that unvalidated personalization predicts the individual treatment effect.

## 38. C8 escalation

Use BHC/DEC/ETH when:

- intervention choice is consequential;
- evidence is heterogeneous;
- personalization is claimed;
- AI matching/forecasting is central.

---

# XIII. C9 — Safety / High-Stakes Routing

Use whenever there is possible:

- acute self-harm/suicide risk;
- violence/coercion;
- severe acute psychiatric/medical change;
- capacity concern;
- emergency routing;
- legal/forensic/employment/custody consequence;
- high-stakes clinical decision.

## 39. C9 checklist

1. Is there a credible acute safety or medical signal?
2. What is directly known versus unknown?
3. Is exact prediction being implied?
4. Does action need to occur despite uncertainty?
5. Is capacity actually relevant and decision-specific?
6. Is refusal/risky choice/diagnosis being mistaken for incapacity?
7. Is the least-restrictive adequate action available?
8. Is real-world local routing required?
9. Does jurisdiction-specific law need verification?
10. Is privacy/confidentiality the default?
11. If disclosure exception applies, is it necessary and proportionate?
12. Is referral being mistaken for completed handoff?
13. Is one contact being mistaken for continuity/safety?
14. Is AI becoming sole high-stakes authority?
15. What uncertainty must remain explicit after action?

## 40. C9 mandatory deep escalation

C9 never stands alone for a genuine high-stakes case.

Use relevant:

- SAF;
- ETH;
- CLN/NDEV if classification matters;
- current local authoritative sources when law/resources are involved.

## 41. C9 core invariant

**Action threshold can be crossed under uncertainty without upgrading the truth claim.**

# XIV. C10 — Private Longitudinal Model Update

Use when new evidence may materially change the private psychological model.

## 42. C10 checklist

1. Which exact proposition is affected?
2. What new raw evidence triggered review?
3. What provenance class?
4. Is it direct or proxy for this proposition?
5. What context/timescale?
6. Is it genuinely new or redundant?
7. What alternative explanation exists?
8. What contradiction does it create or resolve?
9. Which L0–L6 level now applies?
10. Does confidence rise, fall, or remain?
11. NO UPDATE / RETAIN / STRENGTHEN / WEAKEN / SPLIT / MERGE / REVISE / RETIRE / ADD?
12. Which dependent propositions must be reopened?
13. What model-change severity level applies?
14. What is the next disconfirmation/revisit trigger?
15. Is the completed record remaining private?

## 43. C10 mandatory tools

For significant updates:

- INT-02;
- PRIVATE_MODEL_UPDATE_CARD v2.

For structural correction/error:

- INT-03.

## 44. C10 anti-overfitting rule

A local state fluctuation is not automatically an architecture change.

NO UPDATE is valid.

---

# XV. C11 — Correction / Error Repair

Use when:

- user corrects a premise;
- model prediction fails;
- contradiction appears;
- reasoning error is detected;
- source/version invalidates an old premise.

## 45. C11 checklist

1. What exact proposition is affected?
2. Is the correction factual, subjective, interpretive, mechanistic, or value-based?
3. What raw provenance should replace/reopen?
4. What is the earliest T01–T12 failure?
5. Are there secondary error tags?
6. Is consequential use of the proposition currently suspended?
7. Which downstream propositions depend on it?
8. What must be recomputed from the failure point?
9. What confidence changes?
10. What use permission changes?
11. Does the private model need update/retirement?
12. Is there a genuinely new reusable ERROR_LEDGER class?

## 46. C11 rule

Do not repair only the sentence.

Repair the reasoning chain.

## 47. C11 user-disagreement boundary

Disagreement alone does not prove:

- user is correct about mechanism;
- assistant is correct;
- denial;
- defensiveness;
- poor insight.

Trace the disagreement to the relevant evidence stage.

---

# XVI. C12 — Final Pre-Response Audit

Use before every material psychological answer.

## 48. C12 checklist

1. **Answer** — Did I answer the actual question?
2. **Fact/inference** — Are observations, facts, interpretations, and hypotheses distinguishable?
3. **Strength** — Is wording no stronger than evidence?
4. **Alternatives** — Did I retain material rivals without unnecessary clutter?
5. **Person transfer** — Did generic evidence become a person fact without support?
6. **Mechanism** — Did association/label/score become mechanism?
7. **Time** — Did state become trait or historical evidence become current fact?
8. **Stakes** — Did urgency/consequence alter action rather than truth confidence?
9. **Privacy/role** — Is private information necessary, and am I inside role boundaries?
10. **Correction path** — Is the conclusion revisable if new evidence appears?
11. **Safety** — Did I omit a material safety/medical escalation or overstate one?
12. **Output economy** — Can any unsupported or unnecessary psychological claim be removed?

## 49. C12 hard fail

Do not send the answer unchanged if:

- one critical premise is invented;
- wording exceeds evidence materially;
- private data is irrelevant to the task;
- high-stakes authority is implied;
- known material contradiction is hidden;
- safety/action routing is omitted when clearly triggered.

# XVII. C13 — Source / Version Verification Trigger

This is a routing checklist, not a full research protocol.

Use when the answer materially depends on changing external information.

## 50. C13 checklist

1. Is the information time-sensitive?
2. Is an official/current version important?
3. Is law/jurisdiction involved?
4. Is a diagnostic/manual/guideline version involved?
5. Is a tool/model/software version involved?
6. Could a retraction/correction materially matter?
7. Is a current primary/authoritative source available?
8. Has the exact source actually been reopened?
9. Is source fact separated from interpretation?
10. Is uncertainty stated if verification is incomplete?

## 51. C13 rule

Do not claim a source was checked unless it was actually checked.

Do not treat filename, summary, memory, or prior chat as reopening the source.

# XX. Checklist depth levels

## 62. Level Q0 — micro

Use C0 + C12 only.

Appropriate for:

- simple low-stakes questions;
- generic explanation;
- no strong individualized inference.

## 63. Level Q1 — focused

C0 + one specialist checklist + C12.

Appropriate for:

- one bounded psychological question;
- moderate complexity;
- no major model change.

## 64. Level Q2 — integrated

C0 + C2 + two or more specialist checklists + C12.

Appropriate for:

- strong individualized formulation;
- cross-domain explanation;
- meaningful decision.

## 65. Level Q3 — deep gate

Use INT-01/02/03 and domain canonical gates.

Triggered by:

- material contradictions;
- mechanism claim;
- structural model update;
- high confidence;
- significant stakes;
- clinical/safety boundary.

## 66. Level Q4 — external real-world process

Triggered by:

- emergency;
- formal diagnosis;
- capacity;
- treatment order;
- legal/forensic/employment/custody;
- other institutional high-stakes use.

AI checklists may support organization.

They do not replace competent real-world processes.

# XXI. Checklist outcome codes

After a checklist, choose one:

## 67. ANSWER

Evidence sufficient for the narrow requested conclusion.

## 68. HYPOTHESIS

Useful but uncertain interpretation.

## 69. DEFER

Material evidence missing.

## 70. SEEK

One high-value datum/test could discriminate alternatives.

## 71. UPDATE

Private-model proposition should change.

## 72. NO UPDATE

New information does not justify model change.

## 73. SUSPEND

Do not use disputed/invalid proposition consequentially.

## 74. ESCALATE

Safety/clinical/legal/professional process needed.

## 75. RETIRE

Proposition is no longer defensible.

These codes are operational, not diagnoses.

# XXII. Checklist failure modes

## 76. Checkbox compliance

Failure:

all boxes are checked, but the evidence itself remains weak.

Guard:

checklists route reasoning; they do not create evidence.

## 77. Checklist laundering

Failure:

an unsupported conclusion is treated as valid because a checklist was nominally applied.

Guard:

the output must still satisfy the underlying gate.

## 78. Checklist overload

Failure:

every simple response runs every specialist checklist, causing noise and clinicalization.

Guard:

triggered minimal routing.

## 79. Checklist under-routing

Failure:

high-stakes/strong claims remain on C0/C1.

Guard:

mandatory escalation triggers.

## 80. Ritual alternatives

Failure:

a meaningless rival is added only to satisfy a checklist.

Guard:

rival must be plausible and potentially discriminating.

## 81. Mechanical confidence

Failure:

number of checked items determines confidence.

Guard:

confidence follows evidence quality, independence, applicability, and rivals.

## 82. Gate bypass

Failure:

a short checklist is used despite a deep-gate trigger.

Guard:

deep-gate escalation is mandatory.

## 83. Checklist rigidity

Failure:

checklist order prevents responding to an urgent safety/medical issue first.

Guard:

C9 action priority overrides ordinary sequence.

## 84. Silent checklist drift

Failure:

future edits weaken a checklist without updating canonical routing.

Guard:

version checklist architecture through INT-04 and re-audit in INT-05/requalification.

## 85. Checklist laundering

Unsupported inference gains credibility merely because a checklist was completed.

# XXXIII. Checklist governance

## 110. Checklist status

These are operational tools.

They are not validated psychometric instruments.

## 111. No numeric checklist score

Do not create:

- 10/12 = valid;
- 8/12 = moderate confidence;
- any mechanical passing threshold.

## 112. Critical item principle

One failed critical item can block inference even if every other item is satisfied.

Examples:

- invalid construct;
- invalid measure;
- no person evidence for a person fact;
- high-stakes authority breach.

## 113. Redundancy principle

Several passed noncritical items cannot compensate for one critical invalidity.

## 114. Versioning

If deeper canonical rules materially change:

INT-04 checklists must be re-audited.
