# 3. Central taxonomy decision

Advanced mixed-methods frameworks are not additional simple strand-order designs.

They are better represented as:

> **a larger parent architecture that contains one or more basic mixed-method integration patterns.**

Therefore:

- multistage ≠ fourth/fifth basic arrow pattern;
- case study ≠ mixed-method design merely because it uses several data types;
- participatory ≠ mixed methods merely because communities are involved;
- transformative ≠ specific sequence;
- implementation ≠ mixed-method architecture;
- systems science ≠ mixed-method architecture.

### Canonical rule

Store:

**advanced framework / parent program  
+ phase/study map  
+ basic integration pattern within each phase  
+ cross-phase links  
+ program-level meta-inference.**

---

# 4. Multistage / multiphase definition

For RES-02:

> **Multistage/multiphase mixed methods = a program-level architecture in which multiple linked phases or studies use different quantitative, qualitative and mixed-method configurations over time, with outputs from one phase informing later phases and/or being integrated into a higher-order program conclusion.**

Possible sequence:

QUAL exploration  
→ instrument/intervention development  
→ pilot QUAN  
→ definitive trial  
+ embedded convergent process evaluation  
→ post-trial explanatory interviews  
→ program-level synthesis.

### Critical rule

The label “multiphase” does not erase the design of each constituent phase.

---

# 5. Multistage is more than many phases

A research program with five unrelated studies is not automatically multistage mixed methods.

Required features include at least some of:

- shared overarching question;
- explicit phase dependency;
- outputs from one phase build another;
- shared program theory;
- planned cumulative integration;
- final program-level inference.

### Weak architecture

Study A  
Study B  
Study C

with no methodological linkage.

### Strong multistage architecture

Study A findings determine:

- Study B measures;
- Study C intervention;
- Study D explanatory sampling;

and all feed a final program model.

---

# 6. Program-level integration

Multistage programs have two distinct integration levels.

## Phase-level integration

Example:

within Phase 3:

- QUAN + QUAL convergent process evaluation.

## Program-level integration

Example:

Phase 1 QUAL needs  
+ Phase 2 developed intervention  
+ Phase 3 RCT outcome  
+ Phase 3 process findings  
+ Phase 4 sustainability follow-up

→ overall intervention-development/evaluation conclusion.

### Project rule

Store both.

---

# 7. Program-level meta-inference

A program-level meta-inference answers:

> What is known because the phases/studies were intentionally linked across the whole research program?

Examples:

- intervention is culturally acceptable and feasible but not yet effectiveness-tested;
- intervention effect is context-dependent and implementation-sensitive;
- early qualitative determinants were only partly supported quantitatively;
- instrument developed in Phase 1 is adequate for Phase 3 but lacks cross-cultural validation.

### Critical rule

A list of publications is not a program-level meta-inference.

---

# 8. Phase chaining

For each transition record:

`Phase A output → Phase B design decision`.

Possible bridges:

- theme → item;
- barrier → intervention component;
- pilot issue → protocol change;
- RCT heterogeneity → interview sampling;
- process finding → implementation strategy;
- site finding → next-site adaptation.

### Project field

**PHASE_BRIDGE_PROVENANCE**

This is the advanced-program analogue of E4 item/component traceability.

---

# 9. Iteration

Multistage research may loop rather than proceed linearly.

Example:

QUAL need discovery  
→ prototype  
→ pilot  
→ user feedback  
→ redesign  
→ second pilot  
→ trial.

### Critical rule

Iteration is not methodological weakness.

But every major redesign should be versioned.

---

# 10. Intervention version control

Across phases, the “same intervention” may change.

Store:

- version;
- core functions;
- components;
- dose;
- delivery;
- adaptation;
- target population;
- stage.

### Critical rule

Do not attribute Phase 4 outcomes to the exact intervention tested in Phase 2 if it changed materially.

---

# 11. Single-study vs research-program boundary

## Single-study multistage

One protocol/project contains multiple linked phases.

## Research-program multistage

Multiple protocols/publications are intentionally linked under one program.

### Project rule

Use separate fields:

- `PROGRAM_ID`;
- `STUDY_ID`;
- `PHASE_ID`.

This avoids collapsing a multi-year research program into one “study.”

# 26. Single vs multiple case

## Multiple-case mixed methods

Cross-case analysis should not erase within-case context.

# 40. Q Methodology — core scientific object

Q Methodology studies:

> **subjective viewpoints / shared configurations of perspective.**

Canonical architecture:

1. construct concourse;
2. select Q-set;
3. participants rank-order statements/images;
4. intercorrelate Q-sorts;
5. by-person factor analysis;
6. interpret factors/viewpoints using:
   - distinguishing statements;
   - consensus statements;
   - participant comments/interviews.

### Scientific output

- typology/configuration of viewpoints.

---

# 41. Q Methodology is not a conventional basic mixed-method design

Q combines:

- ranked quantitative structure;
- factor analysis;
- qualitative interpretation.

But it does not necessarily contain:

- one independent QUAL strand;
- one independent QUAN strand;
- later integration between them

in the same sense as convergent/explanatory/exploratory designs.

### Project decision

**Q Methodology = standalone methodology-level family**, not a core mixed-method integration design.

---

# 42. Q Methodology can itself be nested inside mixed methods

Possible program:

Q study identifies viewpoints  
→ survey estimates prevalence of those viewpoints  
→ interviews explore implementation implications.

### Then store:

Q Methodology phase  
+ separate mixed-method program architecture.

### Critical rule

Do not double-count the internal Q factor analysis as a generic QUAN strand automatically.

---

# 43. Q Methodology and prevalence

Q seeks:

- existence/structure of viewpoints;
- not population prevalence of viewpoints.

### Critical rule

A Q factor with many defining participants does not estimate:

> percentage of the population holding that view.

Separate representative sampling would be needed.

→ build Q-statements  
→ factor analysis.

# 60. Program-level claim hierarchy

Multistage programs can generate different claim types.

“We built/adapted X.”

## Feasibility claim

“X can be delivered/recruited/measured under these conditions.”

## Effectiveness claim

“X changes outcome Y under the quantitative causal design.”

## Process claim

“X was delivered/experienced through these processes.”

## Implementation claim

“Strategy S changes implementation outcome I.”

## Program-level claim

“Across linked development/evaluation phases, X is ready/not ready for next-stage implementation.”

Do not merge all claims into one evidence strength label.

# 74. Failure mode — transformative label without power analysis

Social-justice wording alone does not establish transformative mixed methods.

# 75. Failure mode — case study without case

A “case study” must define a bounded case.

A topic, population or dataset alone is not a case.

# 76. Failure mode — Q Methodology treated as survey

- participant relevance;
- factor extraction/rotation;
- interpretation.

# 77. Failure mode — Q factors treated as prevalence groups

Factor solution identifies:

- viewpoints.

It does not estimate:

- how common each viewpoint is in the population.

---

# 78. Failure mode — Realist Evaluation called mixed methods automatically

Realist Evaluation can be:

- qualitative only.

Therefore:

realist ≠ mixed.

# 79. Failure mode — CMOC mechanism treated as quantitative mediator

Realist mechanism and statistical mediation are not synonymous.

# 80. Failure mode — systems mapping treated as causal proof

A causal-loop diagram or participatory map can express:

- theorized relationships.

It does not itself establish causal effect magnitudes.
