# 2. Canonical case-study purpose

Case-study research is an in-depth investigation of a clearly defined case, or a small set of cases, in real-world context.

The defining question is not "how many participants are there?" but:

**What exactly is the case, where are its boundaries, and why is this case informative?**

Typical cases include:
- one athlete;
- one team;
- one gym;
- one clinic;
- one intervention program;
- one organization;
- one community;
- one implementation site;
- one event or policy rollout.

Case boundaries may be temporal, spatial, organizational, activity-based or membership-based.

---

# 3. Case, phenomenon and context are different

Example:

- phenomenon: implementation of exercise oncology;
- case: Hospital A exercise-oncology service;
- context: governance, staffing, referral workflow, funding, patient population and local policy.

Several cases can instantiate the same phenomenon under different contexts.

Critical rule:

A broad topic is not automatically a case. If the boundaries are unclear, the study risks becoming an unfocused qualitative project rather than a coherent case study.

---

# 4. Case study is not intrinsically qualitative

Case-study architecture can use:

## Qualitative evidence
- interviews;
- observation;
- documents;
- field notes;
- diaries.

## Quantitative evidence
- attendance;
- performance metrics;
- service data;
- surveys;
- injury rates;
- adherence measures.

## Mixed evidence
Qualitative and quantitative evidence intentionally integrated to understand the case.

Project rule:

Record separately:
1. case-study architecture;
2. qualitative / quantitative / mixed data-method architecture.

Do not classify "case study" as automatically qualitative.

---

# 5. Single-case study

A single-case study investigates one bounded case deeply.

Possible rationales:
- intrinsic importance;
- critical case;
- extreme or deviant case;
- positive deviant;
- unusual or revelatory case;
- typical or illustrative case;
- theoretically informative case;
- longitudinal case.

Critical rule:

One case does not mean one participant.

Example:

Case = one strength-and-conditioning department.

Evidence may include many coaches, athletes, meetings, policies, training logs and performance records.

---

# 6. Multiple-case / collective case study

A multiple-case study investigates two or more bounded cases under a common scientific question.

Goals can include:
- comparison;
- theory testing/refinement;
- contextual explanation;
- recurring mechanism identification;
- contrasting outcomes.

Preferred analysis logic:

within-case interpretation first, then cross-case synthesis.

Pooling all participants across sites immediately can erase the very context the case-study design is meant to preserve.

---

# 7. Replication logic

In Yin-style multiple-case design, case selection can follow replication logic rather than statistical sampling.

## Literal replication
Select cases expected to produce similar findings for theoretically specified reasons.

## Theoretical replication
Select cases expected to produce contrasting findings for theoretically specified reasons.

Exercise example:

Three healthcare sites that have sustained exercise services for at least 12 months can be selected to examine recurring implementation pathways.

Alternative contrasting design:

- sustained service;
- failed service;
- unstable service.

Critical rule:

A set of cases is not automatically a statistically representative sample.

---

# 8. Case-selection strategies

Useful project categories:

- typical;
- critical;
- extreme/deviant;
- positive deviant;
- intrinsic/particularistic;
- instrumental/theoretical;
- polar/contrasting.

Convenient access alone is not a scientific rationale. If convenience drives selection, report it as such.

---

# 9. Holistic vs embedded case structure

## Holistic
One case treated as one main unit.

Example:
one gym as an organization.

## Embedded
One overarching case contains subunits.

Example:

Case:
one professional sports club.

Embedded units:
- first team;
- academy;
- medical department;
- strength-and-conditioning staff;
- return-to-play workflow.

Multiple cases can each contain embedded units.

Critical rule:

Subunit analysis must be re-integrated into the overarching case. Otherwise the study drifts into disconnected subgroup analysis.

---

# 10. Data sources and triangulation

Case studies commonly combine:
- interviews;
- observation;
- documents;
- policies;
- training logs;
- service records;
- surveys;
- video;
- digital communication;
- archival material.

Triangulation can produce:

## Convergence
Different sources support the same interpretation.

## Complementarity
Sources reveal different dimensions.

## Dissonance
Sources conflict.

Dissonance is not an error by default; it can be the key explanation.

Example:

Staff claim adherence is excellent, attendance records show attrition, and participant interviews explain why nominal enrollment overstates actual engagement.

---

# 11. Within-case analysis

Within-case analysis can include:
- chronology;
- narrative reconstruction;
- thematic analysis;
- process mapping;
- logic-model mapping;
- pattern matching;
- explanation building;
- quantitative description;
- rival-explanation assessment.

Reason:

The same outcome can arise through different mechanisms in different cases.

Example:

High adherence may be produced by:
- coaching relationships in Site A;
- automatic referral in Site B;
- transport support in Site C.

---

# 12. Cross-case analysis

Cross-case analysis can examine:
- recurring patterns;
- divergent patterns;
- context-dependent mechanisms;
- rival explanations;
- sequence differences;
- different pathways to similar outcomes.

Canonical sequence:

Case A interpretation + Case B interpretation + Case C interpretation → cross-case comparison → theory refinement / analytic synthesis.

Case identity and context should remain visible.

---

# 13. Data integration

Different source types should be analyzed appropriately before integration.

Example:
- interviews → thematic/framework analysis;
- observation → contextual analysis;
- attendance → descriptive statistics;
- training logs → workload/adherence summary;
- documents → document analysis.

Then integrate them into the case-level explanation.

A table of numbers appended to interviews is not by itself integrated case-study analysis.

---

# 14. Case study vs mixed methods

These are different axes.

Case study defines the bounded-case architecture.

Mixed methods defines intentional integration of qualitative and quantitative methods/data.

Possible combinations:
- qualitative single-case study;
- quantitative-heavy case study;
- mixed-method single-case study;
- mixed-method multiple-case study;
- qualitative case-study component nested inside a larger mixed-method design.

Both data types being present does not automatically mean mixed methods; integration is required.

---

# 15. Analytic generalization

Case studies usually do not aim for statistical population generalization.

Yin-style analytic generalization asks:

How do case findings support, refine, challenge or extend a conceptual/theoretical proposition that might apply in analogous situations?

Logic:

case evidence → theoretical claim → specified conditions of possible transfer.

Do not infer:

Observed in one gym → true in all gyms.

A stronger inference is:

This case supports proposition M under context C; further cases can test whether that proposition replicates.

---

# 16. Not all case-study traditions generalize the same way

Yin-style theoretical/explanatory case studies often foreground theory and analytic generalization.

Stake-style intrinsic/naturalistic case studies can prioritize deep understanding of the particular case itself.

Project rule:

Record the inferential tradition rather than forcing every case study into one generalization model.

---

# 17. Exploratory, descriptive and explanatory case-study purposes

## Exploratory
Clarify what is happening and what requires further inquiry.

## Descriptive
Produce a rich contextual account.

## Explanatory
Ask how and why a pattern occurred.

Explanatory case studies may use:
- pattern matching;
- rival explanations;
- logic models;
- temporal/process evidence.

Critical causal boundary:

An explanatory case study can support a plausible causal explanation, but does not automatically estimate a population causal effect or average treatment effect.

---

# 18. Rival explanations

Strong explanatory case studies should inspect alternatives.

Example explanations for high adherence:
- program quality;
- highly motivated participant selection;
- coach charisma;
- financial incentives;
- team mandate;
- convenient scheduling.

The study can test alternatives using:
- timelines;
- documents;
- interviews;
- observation;
- quantitative trends;
- comparison cases.

A case narrative that only gathers confirming evidence is weaker.

---

# 19. Longitudinal case study

Case studies can follow cases through time.

Useful for:
- implementation rollout;
- organizational change;
- return-to-play systems;
- coaching-system changes;
- periodization redesign;
- facility transitions.

Repeated measurement alone is not a case study. The bounded case and context must remain central.

---

# 20. Boundary with clinical case report

Clinical case report and research case study are different.

## Clinical case report
CARE reporting focuses on:
- patient;
- presentation;
- diagnosis;
- intervention;
- clinical course;
- outcome;
- educational/novel lesson.

## Research case study
Focuses on:
- bounded system;
- context;
- multiple sources/perspectives;
- explicit research question;
- systematic analysis.

Example:

One lifter develops rhabdomyolysis after an extreme session → clinical case report.

How one team's workload norms, monitoring and communication contributed to repeated exertional illness → explanatory case study.

---

# 21. Boundary with N-of-1 / SCED

A one-person case study is not automatically N-of-1 or SCED.

N-of-1/SCED requires repeated experimental comparison, phases or assigned manipulation.

Case study can investigate one person's trajectory/context without experimental assignment.

Example:

Repeated interviews + records during rehabilitation → longitudinal case study.

Repeated randomized caffeine vs placebo → N-of-1 experiment.

---

# 22. Boundary with case-control study

Case study and case-control study are unrelated design families despite the shared word "case".

Case-control:
- cases selected by outcome;
- controls without outcome;
- prior exposure compared.

Case study:
- bounded contextual investigation.

---

# 23. Boundary with ethnography

Case study organizes inquiry around a bounded case/system.

Ethnography organizes inquiry around culture/shared practice/social meaning.

Example:

How did Gym A implement a new injury-prevention workflow? → case study.

How does Gym A socially construct acceptable pain and effort? → ethnography.

An ethnographic case study can legitimately combine both layers.

---

# 24. Boundary with process evaluation

Process evaluation is an evaluation purpose, not one atomic study design.

MRC process evaluation commonly asks about:
- implementation;
- mechanisms of impact;
- context.

It may use:
- quantitative data;
- qualitative methods;
- case study;
- mixed methods.

A process evaluation can use one site as one case or compare sites as cases.

Project rule:

Record separately:
1. process-evaluation purpose;
2. case-study architecture;
3. method/data architecture;
4. parent intervention/trial.

---

# 25. Boundary with implementation science

Implementation case studies can investigate:
- determinants;
- strategies;
- mechanisms;
- adaptation;
- sustainment;
- implementation outcomes.

Record separately:
1. implementation purpose/framework;
2. case-study architecture;
3. case-selection logic;
4. within-case/cross-case analysis;
5. qualitative/quantitative/mixed evidence.

# 27. Exercise-oncology exemplar

A 2023 multiple-case study examined exercise implementation across three Australian healthcare sites.

Evidence included:
- staff interviews;
- documents;
- observations;
- a sustainability survey.

The cases were healthcare implementation sites, not individual interviewees.

The study compared determinants, strategies, mechanisms and implementation pathways across sites.

This illustrates:

participant ≠ case.

# 29. Do-not-confuse matrix

| Do not confuse | Why |
|---|---|
| one participant vs one case | one case can contain many participants/sources |
| one case vs N=1 experiment | case study need not manipulate exposure |
| case study vs clinical case report | contextual research vs clinical episode report |
| case study vs case-control | unrelated design families |
| case study vs qualitative | case study can use qual, quant or mixed evidence |
| mixed data vs mixed methods | integration is required |
| multiple cases vs statistical sample | case selection may use replication/theory logic |
| participant sample vs case sample | different levels |
| embedded units vs separate cases | subunits remain inside overarching case |
| cross-case pooling vs cross-case analysis | context and case identity must remain visible |
| typical case vs probability-representative case | typicality is a rationale, not statistical sampling |
| analytic vs population generalization | theory-based vs statistical inference |
| explanatory case study vs randomized causal effect | explanation is not effect-size identification |
| triangulation vs majority vote | disagreement may be explanatory |
| rich narrative vs rigorous case study | boundaries, sources and analysis still matter |
| ethnography vs case study | culture/practice vs bounded-case organizing logic |
| process evaluation vs case study | evaluation purpose vs design architecture |
