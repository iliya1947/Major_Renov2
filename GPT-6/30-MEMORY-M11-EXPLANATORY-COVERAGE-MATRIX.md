**GPT-6 · 18 октября 2026.** Единственное [задание M11 от GPT-5.6 Sol](https://github.com/iliya1947/Major_Renov2/pull/3#issuecomment-6249476638): проверить **в какой степени** cross-chat Memory объясняет уже документированные **конкретные** ошибки GPT-6. Это observational case-level attribution, **не** выборка из всех ответов GPT-6, не A/B/тест/mitigation. Новых механизмов и новых эпизодов здесь не выдумано.

## 1. Правила матрицы

Статусы **строго по M11**:

1. `MEMORY-SPECIFIC PLAUSIBILITY`: подтверждён специфический прежний/stale item **той же причинной структуры**, существовавший **до** ошибки, при этом гипотеза Memory действительно объясняет нечто существенное **сверх** текущего task/source context. Не требует доказанного retrieval, но **не** выводится из общей схожести слов.
2. `MEMORY-POSSIBLE / NON-SPECIFIC`: возможно прежний контекст усилил выбор, но нет специфического предшествовавшего item/fingerprint или точного as-of exposure.
3. `CURRENT-TURN EXPLANATION SUFFICIENT`: видимый текущий запрос/тест/код/вызов/последовательность решения уже достаточно объясняет конкретный дефект **без необходимости** предполагать Memory. **Это не утверждение, что Memory точно не участвовала**.
4. `NOT ATTRIBUTABLE`: для сопоставления ключевых источников/порядка отсутствуют нужные данные и не установлено даже достаточной текущей причинной картины.

Метки источников: **P1** — исторический ошибочный service routing, зафиксированный в сообщённой Memory 12.10; **P2** — прежнее `#181 hold/not merged`; **P3** — общее `Stage 5 done / Stage 6 in progress` с сохранённым project-wide heading. Они подробно исследованы в [M2](21-MEMORY-M2-HISTORICAL-SNAPSHOT.md), [M3](22-MEMORY-M3-STRUCTURAL-HAZARDS.md), [M4](23-MEMORY-M4-CORRECTED-ERROR-PERSISTENCE.md), [M5](24-MEMORY-M5-UPDATE-LAG.md), [M10](29-MEMORY-M10-ORIGIN-CARRIER-AMPLIFIER.md). Поздний [M7](26-MEMORY-M7-CURRENT-MODEL-VISIBLE-SNAPSHOT.md) нельзя переносить на 11–16.10.

### Не превращать отрицательные контроли в случаи с доказанной причиной

- **Quote повторные FAIL и STOP:** подтверждена реализационная ошибка C06, но не самостоятельный класс `F` без конкретного доответного/дореализационного порога; [joint taxonomy](12-JOINT-STAGE-CONCLUSIONS.md).
- **«Мгновенное нарушение осознанного правила» как D?** В [joint taxonomy](12-JOINT-STAGE-CONCLUSIONS.md) **нет** чистого подтверждённого якоря `D`; не добавлено строкой для увеличения охвата.
- **13.10 полезное «восстановление контекста»** из [M8](27-MEMORY-M8-NATURALISTIC-CROSS-CHAT-USE.md) — **не дефект**, не включён в знаменатель ошибок. Публичные правильные ответы через #147 не доказывают, что Memory была получена и отвергнута.
- **Fast answers caveat:** [методологическая заметка в PR #3](https://github.com/iliya1947/Major_Renov2/pull/3#issuecomment-6249451163) говорит о возможности обхода Memory некоторыми ответами. Из отсутствия fingerprint нельзя выводить «модель получила stale Memory и сознательно проигнорировала её»; для конкретных исторических turns использование fast path не установлено. Не превращать эту заметку в доказательство причин ошибок.

## 4. Прямой ответ M11: степень объяснительного охвата Memory

1. Для **workflow/actor/PR-scope** возможен перенос прошлых привязок. Но даже здесь **P1** (`no service PR`) **не воспроизводится** как уникальное позднее действие; **P2** (#181 hold) в поздних проблемных эпизодах вообще не задействован. Наиболее показательная ошибка **12.10 plan-before-AGENTS** имеет самостоятельное сильное explanation через план внутри текущего хода. Для next-actor 16.10 и audit→#215 остаётся **неспецифическая возможность Memory**, не доказанная Memory-specific causation.
2. Для **технических E/O/V** A-05 rollback, detached textarea, native clipboard proxy, quote AST/CI, Setext/closed ATX — **нет специфичной cross-chat Memory detail**; сами ошибки имеют конкретную техническую проверяемую структуру в текущем code/test/source.
3. Для **G research drift** текущий пользовательский предмет/метод уже задавал нужную границу; сами ошибочные ответы показывают неверный выбор object/method. Прежняя проектная Memory **не добавляет существенного объяснения** по этим эпизодам.
4. **Нельзя сказать, что Memory объясняет существенную часть различных классов GPT-6 ошибок.** На отобранных документированных кейсах гипотеза потенциально релевантна лишь ограниченному классу workflow/scope salience, где пока даже **не достигнут** уровень `MEMORY-SPECIFIC PLAUSIBILITY`. Реальные structural/content hazards Memory из M2–M10 сохраняют значение, но не превратились в downstream behavioral source attribution.
