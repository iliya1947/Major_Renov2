# EXE-02 — Goal representation, proactive/reactive control, and hierarchical task control

Status: **CLOSED_FOR_PRACTICE v1.0**

## Purpose

Deepen the control architecture established in EXE-01 by specifying how goals/task rules are:

- selected;
- represented;
- maintained;
- updated;
- protected from interference;
- organized hierarchically;
- used proactively or reactively;
- reconfigured when context changes.

The block also separates:

- goal representation from goal value/motivation;
- maintaining a task goal from working memory as a whole;
- proactive control from reactive control;
- proactive/reactive modes from stable personality types;
- context representation from immediate stimulus-response mappings;
- abstract context switching from lower-level task-rule switching;
- control-state reconfiguration from generic "flexibility";
- goal persistence from perseveration;
- goal shielding from inability to update;
- control policy from control allocation.

## Core rule

**Goal-directed control depends not only on whether a goal exists, but on how it is represented, maintained, protected, updated, hierarchically organized, and deployed over time.**

A generic architecture is:

`goal selection`
-> `goal/task representation`
-> `maintenance / shielding / contextualization`
-> `proactive preparation or reactive retrieval`
-> `policy / rule selection`
-> `action`
-> `feedback / context update`
-> `maintain, revise, switch, or abandon goal/control state`

## 1. Current official scaffold

NIMH RDoC currently places:

- goal selection;
- goal updating;
- goal representation;
- goal maintenance

inside Cognitive Control.

NIMH distinguishes this from Working Memory, which can actively maintain many kinds of task-relevant information, not only goal representations.

Canonical boundary:

**goal maintenance is a control use of maintained information, not a synonym for all working memory.**

## 2. Goal selection

Goal selection chooses among possible:

- outcomes;
- actions;
- behavioral policies;
- task states.

A selected goal answers:

> What outcome/state should currently guide behavior?

This is distinct from:

- how valuable the goal is;
- how much effort one is willing to spend;
- how the goal is implemented.

Motivational valuation is routed to MOT.

## 3. Goal representation

A goal representation encodes information needed to constrain behavior.

Depending on task, this can include:

- desired outcome;
- relevant context;
- task rule;
- conditional rule;
- stimulus-response mapping;
- subgoal structure;
- priority relation;
- stopping/termination condition.

Canonical rule:

**a goal is not only a verbal intention.**

Goal representations need not be consciously verbal or proposition-like.

## 4. Goal representation is not necessarily discrete

Many cognitive-control models describe goals/task sets as discrete states.

Recent work suggests that at least some goal representations may occupy continuous representational spaces.

A 2025 set-shifting study found that interference from a previous goal changed gradually as representational distance between old and current goals increased.

Therefore:

`goal representation = one isolated symbolic token`

is too strong as a universal account.

The exact format remains an empirical question.

## 5. Task representation

A task representation specifies how context should map onto behavior.

It can include:

- which feature matters;
- which rule applies;
- which response mapping is active;
- which subgoal is current;
- what counts as success/error.

Badre's 2025 review emphasizes that differences in the **content and structure of task representations** are central to cognitive control.

Thus two people can fail the same task for different reasons:

- wrong task representation;
- weak maintenance of the correct representation;
- correct representation but failed implementation.

## 6. Goal/task representation versus control strength

A common error is to explain mistakes by "insufficient control."

But control can fail even with strong engagement if the represented rule/context is wrong.

Canonical distinction:

`wrong representation`
!=
`weak implementation of correct representation`.

This distinction must be checked before any person-level executive inference.

## 7. Goal maintenance

Goal maintenance keeps the currently relevant representation sufficiently available to bias later processing.

Maintenance supports:

- task-set stability;
- resistance to interference;
- preparation;
- delayed action;
- sustained priority.

But maintenance is not always optimal.

When environments are volatile, excessive maintenance can slow updating.

## 8. Goal shielding

Goal shielding protects a current goal/task set from competing goals or distracting information.

Shielding can improve:

- persistence;
- interference resistance;
- dual-task priority.

But excessive shielding can cause:

- rigidity;
- missed context change;
- perseveration;
- slow switching.

Canonical rule:

**goal stability is useful only relative to environmental stability.**

## 9. Goal persistence is not automatically irrational

Recent 2025 review work argues that strong persistence can have adaptive computational functions, including:

- protecting selected goals from interference;
- reducing repeated decision costs;
- preserving motivation when reward signals are weak/noisy.

Therefore:

`continued goal pursuit -> sunk-cost bias/perseveration`

is not automatic.

The relevant question is whether persistence remains adaptive after the environment/goal value has changed.

## 10. Goal abandonment

Abandoning a goal can be adaptive when:

- expected value changes;
- feasibility drops;
- opportunity costs rise;
- new evidence changes strategy;
- higher-level goals change.

But abandoning a goal can also reflect:

- weak maintenance;
- distractibility;
- low motivation;
- uncertainty;
- competing goals.

Behavior alone does not identify the mechanism.

## 11. Goal updating

Goal updating changes the controlling representation when relevant conditions change.

Triggers can include:

- explicit instruction;
- environmental volatility;
- feedback;
- prediction error;
- changed reward/cost;
- higher-level goal revision.

Updating is not identical to switching response mappings.

It can occur at several representational levels.

## 12. Updating rate should match environmental volatility

A stable environment favors retaining a control policy.

A volatile environment favors faster updating.

Recent 2026 evidence from rule-learning tasks shows that people can learn different task-rule updating strategies based on environmental volatility, but stable context-specific strategies may require extensive experience.

Canonical rule:

**fast updating is not globally better; slow updating is not globally worse.**

The appropriate rate depends on volatility and uncertainty.

## 13. Recent experience versus learned environmental knowledge

Rule updating can initially depend heavily on:

- recent feedback;
- recently experienced volatility.

After repeated experience, control may increasingly use learned context-specific environmental knowledge.

Thus a person's updating behavior can reflect:

- current evidence;
- learned context model;
- habit/history.

Do not infer a fixed flexibility trait from one short task.

## 14. Hierarchical goals

Goal-directed behavior is often nested.

Example:

`higher goal -> context -> subgoal -> task rule -> action`.

Higher levels constrain lower levels.

A high-level rule may determine which lower-level mapping is relevant.

Canonical rule:

**not all task rules operate at the same level of abstraction.**

## 15. Hierarchical control reduces combinatorial complexity

Without hierarchy, many contexts × rules × actions would need separate mappings.

Hierarchical representations allow reuse:

- one abstract context can select a lower-level policy;
- lower-level rules can be reused across contexts.

This supports:

- generalization;
- transfer;
- behavioral flexibility.

But hierarchies also create update costs at multiple levels.

## 16. Abstract context and concrete task rules can update differently

A 2026 JNeurosci study dissociated:

- higher-level contextual reconfiguration;
- lower-level stimulus-response/task-set reconfiguration.

Lower-level rule changes were faster and more influenced by perceptual interference.

Higher-level context changes were slower and comparatively protected from irrelevant sensory changes.

This supports a functional distinction between:

- flexible low-level mappings;
- more stable context representations.

## 17. Hierarchical switch cost is not one mechanism

A switch cost can reflect:

- representational reconfiguration;
- residual old-task activation;
- cue processing;
- context retrieval;
- conflict;
- response remapping;
- control-state inertia.

The level being switched must be specified.

Canonical rule:

**"switching difficulty" must name what representational level changed.**

## 18. Task-set inertia

Previously active task representations can persist after they become irrelevant.

This persistence can produce:

- switch costs;
- interference;
- response bias.

Current 2026 work continues to show that both local and global context can shape task-set inertia.

Therefore:

`switch error -> failure to understand new rule`

is not necessary.

The old representation may simply remain active.

## 19. Proactive control

In the Dual Mechanisms of Control (DMC) framework, proactive control involves anticipatory use of goal/context information before a demanding event.

Typical functions include:

- maintaining task goals;
- preparing relevant processing;
- biasing attention/response selection;
- preventing predictable interference.

A canonical temporal form is:

`cue / expectation -> sustained or anticipatory goal use -> upcoming event`.

## 20. Reactive control

Reactive control is recruited after a relevant event/conflict appears.

Typical functions include:

- transient goal reactivation;
- conflict-triggered correction;
- stimulus-driven retrieval of context;
- late adjustment.

Canonical temporal form:

`event/conflict -> retrieve/reactivate goal -> corrective control`.

## 21. Proactive/reactive are modes, not person types

DMC was designed as a framework for variability in control strategy.

Control mode can vary:

- within one person;
- across tasks;
- across contexts;
- with age;
- with incentives;
- with working-memory load;
- with learning.

Therefore:

`proactive person`
or
`reactive person`

should not be used as a stable psychological label without much stronger cross-context evidence.

## 22. Proactive and reactive control are not mutually exclusive

Experimental evidence indicates that proactive and reactive control can operate:

- semi-independently;
- simultaneously;
- in different proportions.

Thus the framework is not a binary switch between two exclusive modes.

Canonical rule:

**proactive/reactive are control dimensions or temporal strategies, not an either/or taxonomy.**

## 23. Proactive is not globally superior

Proactive control can be useful when:

- future demand is predictable;
- context cues are reliable;
- interference is likely;
- maintaining a goal is worth the cost.

But it can be costly when:

- events are rare/unpredictable;
- task context changes frequently;
- sustained maintenance is expensive;
- outdated goals need rapid release.

Reactive control can be efficient in those contexts.

## 24. Reactive is not "failed proactive control"

Reactive control can be an adaptive policy.

It minimizes sustained preparation and mobilizes control when needed.

Therefore:

`reactive control -> deficient executive function`

is false.

Some group differences can reflect shifts in preferred/effective control mode rather than global loss of control.

## 25. Lifespan example does not define the mechanism universally

A 2025 study of 327 adults found reduced proactive-control indices with age while reactive-control indices were comparatively preserved in the tested Stroop paradigm.

This is important evidence that control modes can dissociate.

But it does not prove:

- one universal aging mechanism;
- that every older individual relies on reactive control;
- that proactive control is globally better.

Population evidence remains population evidence.

## 26. AX-CPT is a model-dependent proactive/reactive paradigm

AX Continuous Performance Task manipulates context information across cue–probe sequences.

It is commonly used to index:

- proactive maintenance of cue/context;
- reactive control when conflict appears.

But performance also depends on:

- cue perception;
- working memory;
- learned contingencies;
- attention;
- response bias;
- preparation time.

Canonical rule:

**AX-CPT pattern != pure direct readout of control mode.**

## 27. Associative learning can mimic proactive control effects

Research on AX-CPT shows that learned cue–response contingencies can contribute to patterns commonly attributed to proactive goal maintenance.

Therefore:

`AX-CPT proactive signature -> active goal maintenance proven`

is too strong without controls for associative learning.

This is a key task-impurity warning.

## 28. Proactive control can be implemented differently across task conditions

Recent 2026 eye-movement work found that a proactive-control manipulation could rely more on:

- rapid attentional shifts under shorter cue–probe delays;
- sustained cue maintenance under longer delays.

Thus even the same broad "proactive" behavior can be implemented through different component processes.

Canonical rule:

**control mode != single implementation mechanism.**

## 29. Context processing

Context processing concerns using current or prior contextual information to determine which rule/action applies.

Context can be:

- perceptual;
- temporal;
- rule-based;
- social;
- environmental;
- hierarchical.

A context representation is useful only if it changes behavior appropriately.

## 30. Context representation and task state

Context can determine a latent task state.

Example:

`context A -> rule X`
`context B -> rule Y`.

A failure can arise because:

- context was not detected;
- context was not represented;
- context-rule mapping was not learned;
- context was not maintained;
- correct rule was not implemented.

These hypotheses must remain distinct.

## 31. Context does not automatically impose a control mode

A registered experiment on context representations found limited support for the simple idea that learned context alone automatically determines proactive versus reactive control state.

Therefore:

**context effects on control must be demonstrated, not assumed from task structure.**

## 32. Goal selection and goal implementation are separable

Choosing a goal and implementing it can rely on different computations.

Recent work on goal commitment also argues that selection and implementation can be separated algorithmically.

This matters because a person can:

- select an appropriate goal;
- fail to implement it;

or:

- efficiently implement a poorly selected goal.

Canonical rule:

**good execution does not prove good goal selection.**

## 33. Intention formation and intention retrieval can be separable

Formal work on proactivity suggests at least two distinct meta-control decisions:

1. whether to form/set an intention for a future situation;
2. whether to retrieve/activate that intention when the situation occurs.

This prevents a broad failure such as:

> "didn't do intended action"

from being attributed automatically to one goal-maintenance mechanism.

## 34. Control policy versus control state

A **control policy** specifies how processing/action should be regulated under a class of conditions.

A **control state** is the currently instantiated configuration.

Example:

- policy: prioritize accuracy under high stakes;
- state: current decision threshold / attentional bias / rule activation.

Switching goals may require changing control states even when the broader policy is known.

## 35. Control-state inertia

Control settings do not necessarily jump instantly to a new optimum.

Grahek et al. found that participants undershot target control states after goal switches, with larger adjustment costs when:

- target states were farther apart;
- less adjustment time was available;
- switches were more frequent.

Canonical rule:

**failure to instantly match a new goal can reflect control-state dynamics, not misunderstanding or unwillingness.**

## 36. Control reconfiguration has a cost

Changing:

- caution;
- attention;
- threshold;
- task rule;
- context representation

can require time/processing.

Therefore a system can rationally resist frequent goal/control changes even if each individual goal is understood.

This creates a real tradeoff:

`flexibility ↔ reconfiguration cost`.

## 37. Stability and flexibility are jointly regulated

Goal stability protects current processing.

Goal flexibility allows adaptation.

Optimal behavior depends on environmental demands.

Recent 2026 work continues to investigate modulators of the stability–flexibility balance.

Canonical rule:

**appropriate regulation beats maximal stability or maximal flexibility.**

## 38. Goal hierarchy can create cross-level conflict

Conflict can occur between:

- immediate action and task goal;
- current subgoal and long-term goal;
- two abstract goals.

A 2024 integrative framework argues that conflicts involving more abstract goals occur in larger/more complex action spaces and can require considering more alternatives.

This is a useful framework, not a settled single mechanism for all self-control.

## 39. Higher-level conflict is not simply "more inhibition"

Abstract goal conflict can increase demands on:

- representation;
- search;
- valuation;
- memory;
- planning;
- counterfactual simulation.

Thus everyday self-control or moral conflict should not be reduced automatically to laboratory response inhibition.

## 40. Goal representations interact with learning

Task rules can become:

- better encoded;
- more automatic;
- more context-specific;
- more efficiently retrieved

with practice.

Learning can shift control from:

- active deliberative maintenance;
to
- learned context-triggered policies.

Therefore reduced apparent control effort can reflect successful learning rather than lower control engagement.

## 41. Goal representations interact with working memory

Working memory can maintain:

- goals;
- context;
- rules;
- planned actions.

But goal control adds a functional role:

**the maintained information biases downstream selection.**

A WM representation that is remembered but not used to regulate behavior is not equivalent to successful goal control.

## 42. Goal representations interact with attention

A maintained goal can bias:

- what is selected;
- what is ignored;
- which features are prioritized.

But an attentional effect alone does not establish correct high-level goal representation.

The source of the attentional priority must be identified.

## 43. Goal representations interact with motivation

Motivation/value can influence:

- which goal is selected;
- persistence;
- effort allocation;
- whether proactive maintenance is worth its cost.

But motivational value does not specify the control policy itself.

Canonical boundary:

**wanting the outcome != knowing/maintaining/implementing the correct rule.**

## 44. Goal representations interact with metacognition

Metacognition can inform whether:

- the current goal is being achieved;
- confidence is low;
- strategy should change.

But metacognitive monitoring and goal implementation remain distinct.

A person can know:

> "my strategy is failing"

without successfully constructing a replacement strategy.

## 45. Goal failure should be decomposed

When an intended action fails, candidate loci include:

1. goal never selected;
2. goal selected but representation ambiguous;
3. goal not maintained;
4. wrong context represented;
5. intention not retrieved at the relevant moment;
6. goal retrieved too late;
7. policy known but control state not reconfigured;
8. old task state persisted;
9. competing goal dominated;
10. control was not allocated;
11. motivation/value changed;
12. external constraint blocked action.

Canonical rule:

**failed intention != one executive deficit.**

## 46. Goal-Control Inference Gate

Before interpreting goal-directed control, ask:

### A. Goal identity

1. What exact outcome/action/task state is the current goal?
2. Was the goal actually selected?
3. Is the goal externally instructed or self-generated?
4. Is the goal stable or changing?

### B. Representation

5. What information constitutes the goal/task representation?
6. Is it a discrete rule, graded representation, hierarchy, or uncertain state?
7. Could the representation itself be wrong/ambiguous?
8. Is the task assuming one representational format without testing it?

### C. Context

9. What context determines which rule applies?
10. Was context detected?
11. Was it learned?
12. Was it maintained/retrieved?
13. Could a context-rule mapping error explain behavior?

### D. Maintenance/shielding

14. Must the goal remain active before the event?
15. Could interference or distraction disrupt maintenance?
16. Is shielding adaptive in this environment?
17. Could excessive shielding cause perseveration?

### E. Updating

18. What evidence signals that the goal/rule should update?
19. How volatile is the environment?
20. Is the observed update rate appropriate to volatility?
21. Could recent history rather than stable ability explain the update policy?

### F. Hierarchy

22. What is the higher-level context?
23. What lower-level rule/action does it select?
24. Which hierarchical level changed?
25. Could a cross-level conflict explain the result?
26. Is a lower-level switch cost being interpreted as high-level goal failure?

### G. Proactive/reactive mode

27. Is control deployed before or after the critical event?
28. Are proactive and reactive components measured separately?
29. Could both be active simultaneously?
30. Is one mode being treated as a stable person type?
31. Is reactive control incorrectly treated as deficient proactive control?

### H. Task/model validity

32. Does the paradigm isolate active goal maintenance from associative learning?
33. Could perceptual/WM/attention demands explain the effect?
34. Is one AX-CPT/Stroop measure being used as a pure control-mode index?
35. Are preparation time and learned contingencies controlled?

### I. Reconfiguration

36. Did the goal change, or only the required control setting?
37. How far apart are old and new control states?
38. Was sufficient reconfiguration time available?
39. Could control-state inertia explain incomplete adjustment?

### J. Selection versus implementation

40. Was the goal/policy correctly chosen?
41. Was it correctly implemented?
42. Could a correct policy coexist with a failed control state?
43. Could good execution be serving a poorly selected goal?

### K. Motivation/allocation

44. Was the goal still valued?
45. Was control worth its expected cost?
46. Could low allocation rather than absent capacity explain behavior?

### L. Individual inference

47. Is the pattern repeated across contexts/tasks?
48. Could learning history explain it?
49. What rival mechanism remains?
50. What observation would best distinguish representation, maintenance, retrieval, updating, or allocation failure?

## 47. High-value failure modes

### Failure A — goal = verbal intention

Incorrect.

Correct:

Goals can be represented through task rules, contextual states, outcome structures, and other nonverbal codes.

### Failure B — goal representation = one discrete token

Incorrect as a universal claim.

Correct:

Recent evidence supports graded/continuous representational effects in some goal-switching paradigms.

### Failure C — goal maintenance = all working memory

Incorrect.

Correct:

Goal maintenance is a functional control use of maintained information.

### Failure D — persistence = irrational perseveration

Incorrect.

Correct:

Persistence can protect goals and reduce repeated decision/interference costs.

### Failure E — fast updating = good flexibility

Incorrect.

Correct:

Optimal update speed depends on environmental volatility.

### Failure F — switching cost = one generic flexibility deficit

Incorrect.

Correct:

The hierarchical level, residual state, cue, mapping, and control-state dynamics matter.

### Failure G — proactive and reactive control are mutually exclusive

Incorrect.

Correct:

They can coexist and vary semi-independently.

### Failure H — proactive control = superior control

Incorrect.

Correct:

Its value depends on predictability, maintenance cost, and environmental volatility.

### Failure I — reactive control = executive deficit

Incorrect.

Correct:

Reactive control can be an efficient adaptive policy.

### Failure J — AX-CPT signature proves active goal maintenance

Incorrect.

Correct:

Associative learning, attention, WM, and response factors can contribute.

### Failure K — one control mode = stable person type

Incorrect.

Correct:

Modes vary within person across context, task, incentives, load, learning, and age.

### Failure L — context automatically determines control mode

Incorrect.

Correct:

Context effects on control-state selection must be demonstrated empirically.

### Failure M — failed intention = forgot the goal

Incorrect.

Correct:

Selection, representation, maintenance, retrieval, implementation, allocation, or motivation can fail separately.

### Failure N — slow adjustment = unwillingness

Incorrect.

Correct:

Control-state inertia/reconfiguration costs can delay adaptation even when the new goal is understood.

### Failure O — higher-level self-control conflict = inhibition task

Incorrect.

Correct:

Abstract conflicts can additionally require representation, valuation, planning, search, and goal arbitration.

## Canonical working rule

**Identify the goal, reconstruct how it is represented and hierarchically contextualized, test whether it is maintained or retrieved proactively/reactively, separate goal selection from implementation and control-state reconfiguration, then explain failure only at the mechanism level supported by evidence.**

Never:

**intention failed -> weak executive control / poor willpower.**

## Current-standard note

As of 2026-11-19:

- NIMH RDoC continues to place goal selection, updating, representation, and maintenance within cognitive control while distinguishing working memory as the broader temporary-maintenance construct;
- Badre's 2025 synthesis emphasizes task-representation content and structure as central to context-sensitive control;
- Dual Mechanisms of Control remains a useful framework, but proactive and reactive control should be treated as variable modes/dimensions rather than mutually exclusive person types;
- current 2025–2026 evidence shows that goal/task representations can have graded representational structure, hierarchical levels can reconfigure differently, and update strategy can adapt to learned environmental volatility;
- current control-dynamics work demonstrates genuine reconfiguration/inertia costs when performance goals change;
- AX-CPT and related paradigms remain theoretically useful but can mix active goal maintenance with associative learning, attention, working-memory, and response processes.
