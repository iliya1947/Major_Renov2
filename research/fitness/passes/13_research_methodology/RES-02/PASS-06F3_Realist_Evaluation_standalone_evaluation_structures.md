# RES-02 / PASS-06F3 — Realist Evaluation standalone evaluation structures

Статус: **COMPLETE — REALIST EVALUATION TAXONOMY ESTABLISHED FOR RES-02 STRUCTURAL USE**  
Дата: 2026-11-18  
Topic: RES-02 — Study designs / what they answer

## Purpose

Этот PASS закрывает taxonomy-level архитектуру **Realist Evaluation (RE)** как отдельной theory-driven evaluation methodology внутри F-ветки.

Главная задача:

> сохранить realist evaluation как самостоятельную explanatory methodology с programme theory, generative causation и context–mechanism–outcome configuration logic, не сводя её к generic qualitative research, process evaluation, mixed methods, causal mediation или realist review.

---

# 1. Final project classification

Project route:

**REALIST_EVALUATION**

Realist Evaluation = theory-driven evaluation methodology, основанная на realist philosophy of science и ориентированная на объяснение:

- что работает;
- как;
- почему;
- для кого;
- в каких контекстах;
- в какой степени;
- в каком отношении;
- в течение какого времени.

Core architecture:

1. define evaluand and explanatory question;
2. elicit/build Initial Programme Theory (IPT);
3. express testable realist propositions;
4. identify relevant contexts, mechanisms and outcomes;
5. select cases/data sources because they can test/refine theory;
6. collect qualitative and/or quantitative evidence;
7. analyse through configurational + retroductive reasoning;
8. build/test/refute/refine CMOCs;
9. compare across cases/subgroups/settings/time;
10. refine programme theory;
11. produce conditional explanatory conclusions.

### Critical classification rule

Realist Evaluation is **method-neutral**.

It may use:

- interviews;
- focus groups;
- observations;
- documents;
- routine data;
- surveys;
- trial outcomes;
- economic data;
- mixed evidence.

But the use of several methods does not itself define RE.

The defining layer is:

**realist programme theory + generative causal reasoning + theory-testing/refinement through context–mechanism–outcome patterns.**

---

# 2. Realist ontology / generative causation

Realist Evaluation does not assume that the programme itself mechanically produces outcomes.

Canonical logic:

programme/intervention supplies opportunities/resources  
+ actors/systems respond through generative mechanisms  
+ contextual conditions enable, constrain or alter those mechanisms  
→ outcome patterns.

This is an **open-system** causal model.

Observed regularity is therefore expected to be:

- conditional;
- context dependent;
- potentially different across actors/settings/time.

### Project rule

Do not route realist causation as:

**intervention → outcome**

without the explanatory C–M relationship.

Instead retain:

**context + mechanism → outcome pattern**

with programme resources/intervention components represented separately where useful.

---

# 3. Programme theory

A programme theory states how and why the evaluand is expected to generate outcomes.

In RE it is both:

- a starting hypothesis;
- an object of empirical testing/refinement.

RAMESES II explicitly requires the initial programme theory to be described and the processes used to develop it to be transparent.

Possible IPT sources:

- existing programme documentation;
- logic models;
- policy documents;
- prior research;
- realist or conventional literature review;
- stakeholder interviews;
- expert consultation;
- pilot/exploratory work;
- substantive/middle-range theory;
- prior implementation experience.

### Critical rule

A generic logic model is not automatically a realist programme theory.

A realist programme theory must ultimately specify or support reasoning about:

- contexts;
- mechanisms;
- outcomes;
- their relationships.

---

# 4. Initial Programme Theory (IPT)

Project route:

**INITIAL_PROGRAMME_THEORY**

Minimum extraction:

1. theory source;
2. actors/groups;
3. intervention resource/opportunity;
4. hypothesised reasoning/response;
5. relevant context;
6. expected outcome;
7. temporal ordering;
8. competing explanation;
9. level of abstraction;
10. evidence status.

### Strong IPT

A strong IPT is:

- explicit;
- explanatory;
- testable/refinable;
- sufficiently focused for feasible data collection;
- linked to the evaluation question.

### Weak IPT

Examples:

- “the programme improves engagement”;
- descriptive implementation flow;
- list of intervention components with no mechanism;
- theory of change with no context sensitivity.

---

# 5. Context

Context is not simply:

- demographic covariates;
- study setting;
- background description.

In realist reasoning, context includes conditions that enable, constrain, modify or redirect mechanisms.

Possible levels:

- individual;
- interpersonal;
- professional;
- organisational;
- institutional;
- cultural;
- social;
- economic;
- policy;
- geographic;
- historical;
- temporal;
- technological;
- implementation stage.

### Critical rule

Context is relational to the explanatory question.

A feature may act as context in one CMOC and occupy another explanatory role at a different analytic level.

Therefore:

**context is not a fixed universal variable class.**

---

# 6. Mechanism

Mechanism is the most common source of realist misclassification.

A realist mechanism is not simply:

- intervention component;
- implementation activity;
- participant characteristic;
- mediator variable;
- outcome;
- context.

The RAMESES/realist literature describes mechanisms as underlying generative processes that explain how outcomes are produced.

A useful operational decomposition from Dalkin et al.:

**mechanism = resource + reasoning/response**

where:

- the programme provides a resource/opportunity;
- the actor interprets/responds/reasons about it;
- that response contributes to the outcome under particular contextual conditions.

### Example structure

Resource:
- personalized feedback.

Reasoning/response:
- participant interprets feedback as credible and personally relevant.

Context:
- trusted provider relationship.

Outcome:
- increased adherence.

### Critical rule

The intervention resource itself is not the whole mechanism.

---

# 7. Mechanisms beyond individual cognition

The resource/reasoning formulation is especially useful for social programmes, but project routing must not over-reduce all mechanisms to conscious human reasoning.

Mechanisms may involve:

- individual reasoning;
- affective responses;
- relational processes;
- organisational processes;
- social processes;
- institutional processes.

### Project rule

Record the level at which the proposed generative mechanism operates.

Avoid:

- reifying mechanisms as directly observable variables;
- assuming all mechanisms are conscious;
- treating one conceptualization as universal across all realist traditions.

---

# 8. Outcome

Outcomes may be:

- intended;
- unintended;
- positive;
- negative;
- proximal;
- intermediate;
- distal;
- behavioural;
- clinical;
- organisational;
- implementation;
- system-level.

Outcomes may be represented with:

- quantitative measures;
- qualitative evidence;
- observed patterns;
- administrative/routine data.

### Critical rule

RE does not require outcomes to be qualitative.

It also does not require them to be statistically significant treatment effects.

---

# 9. Context–Mechanism–Outcome Configuration (CMOC)

Canonical route:

**C + M → O**

A CMOC is not a list of three disconnected codes.

It is an explanatory proposition/configuration:

> in context C, resource/opportunity R generates or enables mechanism M, which contributes to outcome O.

Project fields:

1. CMOC ID;
2. C;
3. intervention/resource;
4. actor;
5. M;
6. O;
7. direction;
8. timing;
9. evidence sources;
10. supporting cases;
11. disconfirming cases;
12. confidence;
13. alternative explanation;
14. relation to programme theory.

### Critical rule

“Context / mechanism / outcome” labels without explicit relationships do not constitute a mature CMOC.

---

# 10. Alternative realist configuration formats

Some studies use expanded heuristics such as:

- ICAMO / ICAMOC:
  - Intervention;
  - Context;
  - Actor;
  - Mechanism;
  - Outcome.

These may improve separation of:

- programme resource/intervention;
- actor;
- mechanism;
- contextual condition.

### Project rule

Preserve author configuration format.

Canonical project mapping remains compatible with:

**Intervention/resource + Context + Actor + Mechanism → Outcome.**

Do not treat ICAMO as a separate evaluation methodology.

---

# 11. Realist research cycle

Canonical high-level cycle:

1. develop/clarify initial programme theory;
2. design evaluation around theory;
3. collect evidence capable of testing/refining theory;
4. analyse C–M–O relationships;
5. compare patterns;
6. revise theory;
7. repeat where needed;
8. produce refined programme theory.

### Critical rule

The cycle is iterative.

Theory can change:

- during sampling;
- during interviewing;
- after negative cases;
- after cross-case comparison;
- after new quantitative evidence.

---

# 12. Sampling

Realist sampling is primarily **theory-driven**.

Purpose:

> select people, cases, sites, time points or data sources that can inform, test, contrast, refute or refine parts of programme theory.

Possible strategies:

- purposive;
- criterion;
- maximum-variation;
- contrasting cases;
- extreme/deviant cases;
- theoretical sampling;
- iterative follow-up sampling.

### Critical rule

Representativeness is not the default RE sampling criterion.

Sampling should be justified by:

**what theory component this case/data source can test.**

---

# 13. Case/site selection

Useful comparisons may include:

- high vs low implementation;
- successful vs unsuccessful outcomes;
- different organisational contexts;
- different stakeholder roles;
- different intervention exposure;
- early vs mature implementation;
- contrasting demographic/social contexts;
- discrepant cases.

### Project rule

For each case/site store:

1. why selected;
2. relevant theory proposition;
3. contextual contrast;
4. expected mechanism;
5. observed outcome pattern;
6. whether it supports/refutes/refines theory.

---

# 14. Data source pluralism

RE is explicitly method-neutral.

Possible data sources:

- interviews;
- focus groups;
- observation;
- documents;
- programme records;
- fidelity data;
- clinical outcomes;
- implementation measures;
- surveys;
- routine databases;
- economic data;
- trial data.

### Critical rule

Method selection should follow programme theory.

Weak realist practice:

> choose interview/thematic-analysis methods first, then add C/M/O labels afterward.

The 2022 mapping review identified insufficient theory linkage in methods and sampling as a recurring weakness.

---

# 15. Realist interviewing

Realist interviews differ from generic interpretivist interviews because the interview target is not only:

> “tell me your experience.”

The researcher actively brings theory into the interview.

Manzano describes a teacher–learner relationship in which interviewer and participant exchange knowledge:

- researcher supplies proposed theory;
- participant supplies experiential/domain knowledge;
- theory is confirmed, rejected, specified or refined.

Three useful phases:

1. **THEORY_GLEANING**
2. **THEORY_REFINING**
3. **THEORY_CONSOLIDATION**

### Critical rule

Realist interviews may be more explicitly theory-driven and dialogic than generic phenomenological or descriptive interviewing.

---

# 16. Realist interview sampling

Participants are selected because they have knowledge relevant to:

- programme theory;
- particular contexts;
- mechanisms;
- outcomes;
- implementation roles;
- contrasting cases.

Examples:

- programme designers;
- implementers;
- clinicians;
- recipients;
- non-engagers;
- managers;
- policymakers;
- stakeholders with failed/successful implementation experience.

### Critical rule

Sample adequacy is assessed by explanatory/theoretical contribution, not only saturation.

---

# 17. Realist interview content

Interview questions may probe:

- what happened;
- for whom;
- under which conditions;
- what resource/opportunity was available;
- how the actor interpreted/responded;
- why a different response occurred elsewhere;
- whether a proposed CMOC is plausible;
- exceptions;
- rival explanations.

### Project rule

Store whether interview was:

- theory gleaning;
- theory testing;
- theory refining;
- consolidation;
- mixed phase.

---

# 18. Analysis: deduction, induction, abduction, retroduction

RE analysis commonly combines several modes of inference.

## Deduction

Test pre-existing programme-theory propositions against data.

## Induction

Identify patterns/new concepts emerging from empirical evidence.

## Abduction

Re-describe or recontextualize findings using theoretical ideas that may explain them.

## Retroduction

Reason backward from observed outcome patterns toward the hidden generative conditions/mechanisms that would need to exist for those outcomes to occur.

### Critical rule

Retroduction is not:

- ordinary backward description;
- statistical reverse causality;
- simply coding data as C/M/O.

It is explanatory inference about underlying causal structure.

---

# 19. Retroductive transparency

Recent methodological work highlights that retroduction is often hidden in reports.

Project requires explicit provenance:

1. observed pattern;
2. candidate explanation;
3. theory/source used;
4. inferred mechanism;
5. inferred enabling/constraining context;
6. competing explanations;
7. evidence checked;
8. stakeholder challenge;
9. refined CMOC.

### Critical rule

A plausible mechanism is not established merely because the evaluator can imagine it.

The inference must be confronted with empirical evidence and alternatives.

---

# 20. Theory testing / refinement

Each CMOC may be:

- supported;
- partially supported;
- refuted;
- split;
- merged;
- narrowed;
- expanded;
- recontextualized.

Programme theory may change in:

- mechanism specification;
- context boundary;
- actor subgroup;
- expected outcome;
- timing;
- resource–reasoning relation.

### Critical rule

Failure of an IPT is informative.

RE should not force all data to fit the initial programme theory.

---

# 21. Negative / disconfirming cases

Disconfirming cases are especially valuable because they may expose:

- missing context;
- alternative mechanism;
- threshold condition;
- unintended outcome;
- implementation failure;
- incorrect theory.

### Project rule

Store:

- expected CMOC;
- observed mismatch;
- whether data quality issue excluded;
- alternative context;
- alternative mechanism;
- refined theory.

### Critical rule

Do not suppress negative cases merely to make the programme theory coherent.

---

# 22. Cross-case configurational comparison

RE often gains explanatory power by comparing:

- cases;
- sites;
- subgroups;
- periods;
- implementation states.

Goal:

> identify recurring conditional C–M–O patterns rather than one unconditional average relation.

### Project rule

Store both:

- within-case CMOCs;
- cross-case pattern/refinement.

Do not jump directly to cross-case theory before preserving case-specific configurations.

---

# 23. Quantitative evidence inside RE

Quantitative evidence can contribute to:

- outcome magnitude;
- outcome pattern;
- subgroup variation;
- temporal trends;
- exposure/dose;
- implementation fidelity;
- contextual differences;
- economic outcomes;
- testing specific theory predictions.

### Critical rule

Quantitative evidence does not cease to be quantitative because it appears in a realist evaluation.

Its inferential properties remain those of the underlying design.

Example:

RCT effect estimate  
+ RE explanation

→ randomized effect inference remains owned by RCT.

---

# 24. Mixed methods inside Realist Evaluation

RE may use both QUAL and QUAN.

But:

**REALIST_EVALUATION ≠ MIXED_METHODS by definition.**

Project representation:

REALIST_EVALUATION parent methodology  
+ exact QUAN parent design  
+ exact QUAL parent methodology/methods  
+ mixed-method route only if intentional QUAL–QUAN integration meets E-branch criteria.

### Critical rule

Method plurality is insufficient for generic MMR classification.

---

# 25. Realist Evaluation vs realist review / realist synthesis

These are separate routes.

## REALIST_EVALUATION

Primary evaluation of an evaluand/programme/policy/initiative using empirical data.

## REALIST_REVIEW / REALIST_SYNTHESIS

Evidence-synthesis methodology using existing literature/evidence to develop/test/refine programme theory.

### Critical rule

A realist review may:

- precede an RE;
- supply an IPT;
- run alongside it.

But it is not the same design.

Project ownership:

- primary RE → current RES-02 route;
- realist review → later evidence-synthesis taxonomy.

---

# 26. Realist Evaluation vs process evaluation

Process evaluation and RE overlap but are not synonyms.

A process evaluation may examine:

- implementation;
- fidelity;
- dose;
- reach;
- mechanisms;
- context;
- participant response.

It may use:

- descriptive;
- theory-based;
- mixed-method;
- realist;
- other frameworks.

### Project rule

If realist ontology/programme-theory/CMOC logic is genuinely enacted:

**PROCESS_EVALUATION purpose + REALIST_EVALUATION methodology**

may coexist.

If a process evaluation only describes implementation processes:

it is not automatically realist.

---

# 27. Realist Evaluation nested in trials

RE can be nested alongside:

- RCT;
- cluster RCT;
- stepped-wedge trial;
- pragmatic trial;
- quasi-experiment.

Randomization is not philosophically incompatible with realist explanation.

### Project rule

Keep separate:

1. trial causal estimand;
2. RE programme theory;
3. context-mechanism explanation;
4. integration between them.

### Critical rule

The realist component does not weaken or replace trial randomization.

The trial does not automatically identify the realist mechanism.

---

# 28. Realist mechanism vs statistical mediation

These concepts must remain separate.

## Realist mechanism

- generative;
- often partly hidden;
- context dependent;
- may involve resource + reasoning/response;
- formulated in programme theory;
- tested through configurational evidence.

## Statistical mediator

- measured/intervening variable in a causal/statistical model;
- requires explicit causal assumptions;
- may estimate direct/indirect effects under conditions covered in PASS-06C3.

### Critical rule

A mediator variable is not automatically a realist mechanism.

A realist mechanism is not automatically a measured mediator.

A mediation analysis may provide evidence relevant to one part of a realist programme theory, but does not replace realist explanation.

---

# 29. Realist mechanism vs biological mechanism

Realist mechanisms frequently refer to:

- reasoning;
- responses;
- social interaction;
- organisational process;
- institutional process.

They are not automatically:

- molecular;
- physiological;
- biomechanical.

### Project rule

If an exercise/rehabilitation programme theory includes biological pathways:

retain them separately as mechanistic evidence governed by PASS-06C.

Do not blur:

**programme-theory mechanism**  
with  
**biological mechanism**.

---

# 30. Causal claim boundary

RE does make causal explanatory claims in the realist/generative sense.

However this does **not** mean every RE independently identifies:

- unbiased treatment effect;
- causal mediation;
- counterfactual effect size;
- population average treatment effect.

### Project rule

Separate:

1. **GENERATIVE EXPLANATION**
   - how/why/for whom/context.

2. **COUNTERFACTUAL EFFECT ESTIMATION**
   - owned by randomized/quasi/causal-design architecture.

### Critical rule

A strong CMOC can support a plausible/refined causal explanation without becoming a substitute for a randomized effect estimate where such an estimate is required.

---

# 31. Transferability / generalization

RE seeks theoretical or explanatory transferability rather than simple population-frequency generalization.

A refined programme theory may support predictions such as:

> when context C is present, mechanism M is more likely to operate and produce outcome O.

### Critical rule

Transferability requires:

- sufficiently specified context;
- mechanism;
- actor;
- outcome;
- boundary conditions.

Do not write:

> “the intervention works everywhere because the programme theory was confirmed.”

---

# 32. Middle-range theory

Some realist evaluations seek to develop/refine explanations at a middle range:

- more abstract than one local programme;
- less universal than a grand theory;
- potentially applicable across related programmes/settings.

### Project rule

Store separately:

- local programme theory;
- candidate middle-range theory;
- empirical support across sites/programmes.

### Critical rule

A local CMOC does not automatically become a transferable middle-range theory.

---

# 33. Implementation-science relationship

RE is highly compatible with implementation research because implementation outcomes are often context dependent.

Possible targets:

- adoption;
- fidelity;
- acceptability;
- feasibility;
- appropriateness;
- reach;
- sustainment;
- implementation strategy response.

### Critical rule

RE is not itself:

- CFIR;
- RE-AIM;
- implementation strategy taxonomy;
- implementation-effectiveness trial.

These can coexist as separate layers.

# 34. Current rehabilitation / physiotherapy relevance

Direct relevance is strongly verified.

## FRONTIER — 2024

A mixed-method realist evaluation of first-contact physiotherapy for musculoskeletal disorders evaluated clinical/cost outcomes alongside realist explanatory work.

Project lesson:

- effectiveness/economic analyses retain their parent quantitative identities;
- realist work explains conditional mechanisms/context.

## REFORM — 2025

A process evaluation of remote vs face-to-face physiotherapy used:

- Realist Evaluation;
- RE-AIM;
- alongside a pragmatic/equivalence trial.

Project lesson:

RE may be:

**process-evaluation purpose + realist methodology + trial parent design + implementation framework**

without any layer replacing the others.

## Long COVID rehabilitation — 2025

Realist-informed qualitative work refined programme theory for a rehabilitation intervention.

Project lesson:

“realist-informed” must be distinguished from a full standalone RE if the complete realist cycle is not enacted.

## Neurorehabilitation — 2026

A current realist evaluation in young adults with acquired brain injury demonstrates continuing direct rehabilitation relevance.

### Exercise/sport implication

RE is most relevant when the question concerns:

- adherence;
- coaching;
- implementation;
- rehabilitation delivery;
- digital/home exercise;
- service models;
- complex behaviour-change programmes;
- contextual heterogeneity.

It is usually not the primary design for:

- hypertrophy effect size;
- strength effect size;
- acute physiology;
- diagnostic accuracy.

# 35. FULL_REALIST vs REALIST_INFORMED

Project classifier:

## FULL_REALIST_EVALUATION

Requires at minimum:

1. explicit realist explanatory purpose;
2. programme theory;
3. context/mechanism/outcome reasoning;
4. theory-driven data collection;
5. empirical testing/refinement;
6. refined realist explanation.

## REALIST_INFORMED

Uses realist concepts but does not enact the full evaluation cycle.

Possible examples:

- qualitative study using realist lens;
- thematic analysis organised around C/M/O;
- process evaluation borrowing realist language;
- study refining one part of a prior programme theory.

### Critical rule

Do not upgrade “realist-informed” to full Realist Evaluation solely because the paper uses CMOC terminology.

# 36. Quality architecture

RAMESES II Quality Standards organize appraisal around the coherence and explanatory adequacy of the realist approach.

Project quality layers:

## Q1 — Realist fit

- question requires explanation;
- realist approach appropriate;
- philosophy/logical basis coherent.

## Q2 — Programme theory

- IPT explicit;
- development transparent;
- plausible;
- testable;
- linked to methods.

## Q3 — Sampling/data

- theory-driven;
- relevant actors/cases;
- contrasting evidence;
- data sources fit theory.

## Q4 — Analysis

- C/M/O relationships explicit;
- retroduction transparent;
- alternative explanations considered;
- negative cases used;
- theory actually refined.

## Q5 — Explanatory product

- CMOCs coherent;
- context boundaries clear;
- mechanisms generative rather than component labels;
- outcome patterns supported;
- final theory traceable.

## Q6 — Claim calibration

- effect inference not overstated;
- mediation not conflated;
- transferability bounded;
- uncertainty retained.

## Q7 — Reporting/provenance

- reconstructable evaluation;
- RAMESES II reporting;
- data-source provenance;
- analysis trail;
- theory revisions documented;
- AI/tool provenance.

# 38. RAMESES II Quality Standards

The RAMESES II project also provides quality standards for:

- evaluators/peer reviewers;
- funders/commissioners.

- asks explanatory realist questions;
- uses a coherent realist logic;
- makes programme theory explicit;
- gathers evidence capable of testing theory;

### Project rule

Use these standards as a methodology-specific quality lens.

Do not collapse them into a single arbitrary project score.

# 39. Common failure modes

1. **CMO labelling without causal configuration**
   - codes are separated but relationships are absent.

2. **Mechanism = intervention activity**
   - programme component mislabeled as mechanism.

3. **Mechanism = mediator**
   - statistical variable substituted for generative explanation.

4. **Context = demographics list**
   - no enabling/constraining causal role.

5. **Generic thematic analysis + realist label**
   - theory is not actually tested/refined.

6. **No explicit IPT**
   - impossible to reconstruct what was tested.

7. **Sampling by convenience only**
   - no link to theory.

8. **Only supportive cases**
   - no negative/disconfirming evidence.

9. **Programme theory never changes**
   - evaluation becomes confirmation exercise.

10. **Realist review confused with RE**
   - evidence synthesis misclassified as primary evaluation.

11. **Mixed methods assumed**
   - multiple data sources are treated as automatic MMR.

12. **Effectiveness overreach**
   - explanatory qualitative evidence treated as proof of intervention efficacy.

13. **Local theory overgeneralized**
   - context boundaries disappear.

14. **Retroduction hidden**
   - mechanism inference is not auditable.
