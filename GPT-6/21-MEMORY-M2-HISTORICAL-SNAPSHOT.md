## 1. Находка: документированный снимок памяти от 12 октября

В личной Library обнаружен ранее сохранённый **model-generated** документ `dolgovremennaya_pamyat_lichnye_dannye_polnaya_vygruzka.md`:
- metadata создания файла: **2026-10-11 22:04:21 UTC** (= **12 октября 01:04:21 Asia/Jerusalem**);
- собственная дата в документе: **12 октября 2026**;
- в начале заявлен источник: **«только доступный модели в этой беседе блок User Knowledge Memories ... и две записи, явно направленные в долговременную память в ходе этой беседы»**; автор отдельно исключил историю, файлы и connected apps;
- автор прямо предупреждает: **«не гарантированно полный системный экспорт»**, актуальность фактов **не проверялась**.

**Доказательственный статус:** это **датированная выгрузка того, что прежний ChatGPT сообщал как model-visible Memory** в том разговоре. Она гораздо ближе к историческому memory state, чем нынешняя Memory summary, но **не** технический retrieval-log, **не** источник того, что Memory получила *другая* GPT-6 в конкретный ход, и **не** подтверждение, когда внутри Memory был первоначально создан каждый пункт.

Вторая Library-запись `personal_data_memory_audit_ru.md` также датирована **12 октября**, но она прямо предупреждает, что объединяет текущий профиль, сохранённый контекст и сведения из прежних бесед. **Не использовать её как отдельный чистый memory snapshot**; она corroborates только общую осторожность о происхождении данных.

**Конфиденциальность:** полная исходная выгрузка содержит личную и не относящуюся к исследованию информацию. В публичный PR #3 она **не копируется**; ниже извлечены только минимально необходимые старые process/project-state пункты.

**Два разных вида staleness:**
- **Фактическая устарелость** M2-W1 подтверждена сопоставлением вывода о «неиспользовании служебных PR» с реальной рабочей активностью служебного PR #147 **до 12.10**.

Это свидетельствует о **неполноте именно данной выгрузки**, но не доказывает, что память *скрывала* эти сведения или мешала принять новую инструкцию.

**Осторожность с динамикой:** тот факт, что PR #218 был merge позже 12.10 snapshot, означает, что нельзя называть его новый регламент «правилом, уже существовавшим в snapshot». Другое дело — действовавшие на 08.10 практики #147: они предшествуют снимку.

## 3. Memory-first поиск fingerprints в поздних ошибках

### 3.1 Старый service-PR процесс — содержательно сильный memory-item, но fingerprint не найден

**Наблюдаемый old item:** Codex в implementation PR, отказаться от service PR. **Наблюдаемая новая практика:** техническая коммуникация через #147 уже на 08.10. **Проверка поздних бесед по сохранённым фрагментам:** 
- 12.10 GPT-6 сообщала, что взаимодействие с Codex идёт через **#147**, не #215;
- 14.10 после STOP по code-block GPT-6 обращалась к Codex **через #147**;
- 15.10 GPT-6 упоминала результаты/заключения в **#147**, а технические изменения — в #215;
- 16.10 ошибки передачи/подачи очередного review встречались, но они касались конкретного формата действий/адресата, а не подтверждённого следования пункту «служебный PR отменён».

**Результат:** **нет документированного совпадения специфической старой инструкции** с вредным действием GPT-6 после 12.10. Это отрицательное наблюдение в ограниченной выборке, **не** доказательство, что Memory не доставлялась.

### 3.2 «GPT-6 → Codex» вместо новой Sol-boundary

12.10 в рабочем диалоге GPT-6 признала, что сначала выстроила план, затем прочитала новый AGENTS и не перепланировала. Это имеет **частичное смысловое пересечение** со снимком, где Sol как leader ещё не фигурирует, но не уникальное совпадение: прежняя схема была в текущем рабочем контексте и реальных GitHub процессах. Новый ролевой PR #218 merge только **23:09 UTC 12.10**, после snapshot; для точной квалификации конкретного ответа требуется датировать именно его относительно обновления `AGENTS.md`.

**Классификация:** `MEMORY POSSIBLE BUT UNPROVEN`, а источник прежнего плана `NOT ATTRIBUTABLE`. Не повысить до likely из-за совпадения общего слова «Codex».

### 3.3 PR #215 при общем аудите тестов

12.10 memory snapshot перечисляет старые PR, включая #176, но **не содержит #215** (активный Editor implementation). Поэтому **он не подтверждает** memory-origin salience именно PR #215 в ошибочном общем аудите. Для вывода о влиянии нужны либо *другой датированный memory-item с #215*, либо record о реально извлечённой cross-chat памяти. Ни того ни другого в M2 не найдено. PR #215 был публично доступен в GitHub и в текущих рабочих чатах.

**Классификация:** `NO POSITIVE MEMORY FINGERPRINT FROM FOUND SNAPSHOT / SOURCE NOT ATTRIBUTABLE`.

### 3.4 Общий Stage 5/6 vs Editor Stage 5/6

12.10 memory snapshot описывает общий Stage 5 done / Stage 6 in progress. Пользователь позднее исправил путаницу GPT-6 между редакторским и общим roadmap. Однако без уникального ошибочного заимствования из memory-item и при наличии тех же названий в открытых docs/промптах этот случай **не** доказывает cross-chat retrieval. Не объявлять истинный memory-item устаревшим просто потому, что `Editor Stage 5` ещё не был принят.

**Классификация:** `POSSIBLE BUT UNPROVEN`, но `NOT ATTRIBUTABLE`.

## 4. Независимые ограничения происхождения

1. **Найден ровно один документ, который прямо заявляет выгрузку конкретного `User Knowledge Memories` на историческую дату.** Вторая выгрузка по существу — смесь профиля и контекста; её не использовать как независимо подтверждённый memory state.
2. Воспроизведённое содержимое снимка — **вторичная передача ассистента**, не signed platform memory backend log. Нельзя доказать byte-to-byte точность каждой строки memory или точную дату создания пунктов до 12.10.
3. Показана доступность старого process item **одному ChatGPT** 12.10; неизвестно, был ли он **selected/retrieved для GPT-6** в том или ином ошибочном ответе 12–16.10.
4. **Текущая** User Knowledge Memories содержит более поздние роли/PR. Это нельзя использовать как доказательство содержания 12.10 и нельзя «закрыть пробел» переносом современных пунктов назад.
5. Не найден доответный скрытый Memory Source trace для случаев, где GPT-6 ошибалась. По [M1](20-MEMORY-M1-ATTRIBUTION.md), для причинного вывода требуется `historical memory item → retrieved/available → used → contributed to error`, а не только похожие слова.
6. Открытые chat-history excerpts показывают лишь выбранные строки. Нет гарантированно полного snapshot system/project/current/user/tool context к каждому позднему ответу; без него нельзя устранить альтернативы.
