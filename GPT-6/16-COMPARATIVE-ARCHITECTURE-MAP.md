# 16. Архитектурная карта подтверждённых G/E/O/V: что действительно можно вынести за пределы GPT-6

**2026-10-16 · GPT-6.** Основание: [задание Sol после независимой проверки V](https://github.com/iliya1947/Major_Renov2/pull/3#issuecomment-6213619002), [Joint Stage Conclusions v1](12-JOINT-STAGE-CONCLUSIONS.md), разборы [G](07-CONTRACT-PILOT-V2.md), [E](13-E-PRE-ACTION-GATE-FEASIBILITY.md), [O](14-O-ORACLE-ENFORCEMENT.md), [V](15-V-SPEC-DERIVED-COVERAGE.md). **Статус:** сравнительный синтез GPT-6 **до независимой проверки Sol**. Реальных новых interventions, A/B и изменений implementation/CI нет.

**Главный вопрос:** существует ли единая архитектурная граница между **внешним фактом**, **независимой машинной оценкой** и **правом GPT-6 совершить действие**, и что в ней действительно меняется для четырёх классов?

**Важно:** значения «внешний источник» здесь не равны «независимый judge». Текст пользователя, журнал БД и грамматика являются **внешними данными**, но выбор релевантного условия/причины/проверки может оставаться полностью за GPT-6.

## 2. Три разные границы; смешивание даёт фиктивные гарантии

**A. External reference (какие факты/условия доступны).** Оригинал user request, code/logs, DOM/clipboard, CommonMark corpus. Они ограничивают правдоподобные утверждения, **если** модель или runner получает правильный фрагмент. Файл в GitHub или указание SHA не гарантирует полноту выбранного контекста.

**B. Executable judgement (какое утверждение машина способна отклонить).**
- Для **O** уже можно точно утверждать `connected === true` или `clipboard === expected source`, но правильность выбора *самого* observable задаётся извне.
- Для **V** можно независимо от GPT-6 перечислить **синтаксические входы**; применение пользовательской операции требует дополнительного независимо согласованного metamorphic invariant.
- Для **E** наличие пары `error → warning` не доказывает causal attribution; общего машинного predicate для произвольной причины в текущем процессе не установлено.
- Для **G** даже полностью сохранившийся user text не превращается в executable завершение сложной задачи без внешнего семантического автора/судьи.

**C. Enforced action boundary (какое действие становится невозможно).** Чтобы не дать GPT-6 сделать **первую неправильную mutation**, все её write-paths должны быть недоступны для прямого обхода, а решение контроллера должно поступать **до** mutation. В Vico Forum текущее GitHub подключение допускает прямые `push/admin` mutations, а CI исполняется после commit. Sol/Codex approval и CI могут предотвратить **принятие** дефектной версии, но не первую попытку её записи. Нельзя назвать checkpoint настоящим hard gate, если модель вправе его пропустить.

Один рабочий контроль может иметь A, но не B (E); A+B, но не C (O/V); либо только экспериментальный протокол A+B с отсутствующей runtime независимостью (G).

## 3. Проверка гипотезы о внешнем контроле — по каждому классу, включая контрпримеры

**Гипотеза в точных границах:** «Если критическое решение можно заменить *корректно выбранным и реально исполненным* внешним артефактом/тестом, то проверка этого **ограниченного свойства** меньше зависит от субъективной самооценки GPT-6».

- **O — подтверждена как техническая возможность для выбранного observable.** Runtime `isConnected` и clipboard comparison возвращают объективный результат. Но модель может выбрать/не выбрать тест, поэтому **не установлено**, что частота исходных ошибок GPT-6 уменьшается.
- **V — подтверждена как способ внешне задать часть пространства входов.** Deterministic spec selector отбирает и неприятные варианты, которые GPT-6 пропустила. **Но** синтаксическая грамматика не авторизует project-specific преобразование текста и не выбирает самостоятельно область применимости. Реальный A/B/corpus-run ещё отсутствует.
- **E — гипотеза ломается как схема автоматического decision gate.** Даже правильный pinned log **не сообщает**, какие конкурирующие causal hypotheses исключены. Замена памяти модели на immutable log не заменяет причинный вывод на объективный predicate. В A-05 имеющийся источник помог опровергнуть заявление *после* review, не остановил его до публикации.
- **G — гипотеза ломается для задачи с семантическими условиями без внешнего интерпретатора.** Immutable текст запроса сохраняет **слова**, но не машинную истину о том, достигнута ли исходная цель. Independent prepared contract экспериментально может уменьшить свободу GPT-6 пропустить требование *на финише*, но нужна независимая качественная семантическая разметка, а не повторное «сверься с запросом».

**Следовательно:** внешний artifact уменьшает только ту степень свободы GPT-6, которую реально и правильно **замещает**. Сам факт `external / immutable` не создаёт `semantic predicate`, не обеспечивает mandatory execution и не контролирует действие.

### Контрпример «ложной внешней гарантии»

Можно прикрепить к каждому PR immutable ссылку на спецификацию и при этом:
1. GPT-6 выберет неверный раздел (V);
2. тест корректно подтвердит кнопку Copy, хотя пользователь просил native Ctrl+C (O);
3. лог окажется настоящим, но причинная версия неверной (E);
4. авторская сводка задачи пропустит исходный метод пользователя (G).

Во всех четырёх случаях *внешний артефакт существует*, но целевой ошибке он **не препятствует**. Ни одна единая процедура «приложи доказательства» не устраняет этих семантических разрывов.

## 4. Какая архитектурная основа следует из результатов, а какая — нет

**Следует как проектный принцип, НЕ готовая система:**

```text
Исходное требование / domain-spec (за пределами финальной самооценки GPT-6)
        ↓       (scope mapping: кто и почему выбрал этот участок?)
Внешний неизменённый input/corpus или реально исполняемый runtime observable
        ↓       (операционный invariant: что конкретно считать PASS/FAIL?)
Точечный машинный тест на соответствующий observable/варианты
        ↓       (когда тест запускается: до patch? после commit? до acceptance?)
Внешний actor/enforcement с реальным правом STOP/RETURN/REJECT
```

Каждая стрелка — отдельная проверяемая зависимость. Если по любой из них отсутствует независимое основание, говорить об общей «архитектуре надёжности GPT-6» преждевременно.

**Из нашего материала не следует:**
- что такая цепочка уже целиком реализована;
- что большинство важных ошибок GPT-6 относится к O/V;
- что более строгие тесты всегда экономят время и не вызывают ложных остановок;
- что можно преобразовать любую человеческую задачу в конечный conformance corpus;
- что независимая от GPT-6 подготовка контракта не будет ошибочной;
- что «первую ошибку» обязательно нужно блокировать для практической пользы. Контроль **после первого commit, но до следующего неправильного шага** может оказаться полезным, однако это нужно измерить.

**Две независимые практические оси:** `качество выбранного внешнего oracle/coverage` и `обязательность / своевременность применения`. Механизм с хорошим oracle, но без execution, и механизм с обязательным тестом неправильного свойства могут оба не защищать пользователя.

## 5. Что разрешено делать по этим данным сейчас

1. **Без новых общих инструкций:** не менять `AGENTS.md`, не вводить universal evidence form/контракт/чеклист.
2. **Оставить существующую Sol/Codex acceptance boundary** базовым независимым контролем; не выдавать её за новый механизм.
3. **Признавать реальные локальные меры:** для O — valid live DOM и native user-path tests; для V — spec-derived coverage с externally chosen scope и project invariant. Они полезнее self-assessment **для конкретных свойств**, если реально исполняются, но не закрывают общий вопрос GPT-6.
4. **Граница G/E:** при нынешней технической доступности не найден обязательный универсальный pre-action semantic gate. Pilot v2 для G — только будущий контролируемый эксперимент.
5. **Практически релевантная следующая проверка** после согласования карты — **не новые правила**, а измерение эффекта *одного* узкого исполняемого контроля на новых аналогичных задачах: доля реально найденных дефектов до финального review, дополнительных CI/patch итераций, ложных FAIL, затраты runner и исправления/вмешательства пользователя. Без независимого runner и контрольной baseline нельзя утверждать, что найдено улучшение поведения GPT-6.

**Окончательный статус этого документа:** карта возможных externalization points, а не внедрение enforcement. Исходная пользовательская цель — меньше ошибок и исправлений GPT-6 — **пока не достигнута и не измерена**.

## 6. Вопрос Sol для независимого review

Согласна ли ты, что **external data, executable oracle и compulsory action boundary являются тремя разными уровнями**, причём:
- **O/V** обладают положительными узкими кандидатами A+B без C;
- **E** обладает A, но не доказанной универсальной B/C;
- **G** имеет буквальный источник A, но без независимой семантической интерпретации нет B/C в обычном ChatGPT;
- ни один из четырёх не даёт здесь полного enforced pre-first-mutation gate?

Если возражаешь, укажи конкретную ошибочную ячейку карты и её исходное свидетельство. До внешней проверки не объявлять карту совместно утверждённой.
