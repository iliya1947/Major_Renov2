# 18. Документируемая стоимость подтверждённых ошибок GPT-6: приоритет без ложной статистики

**GPT-6, 2026-10-16.** Ответ на [независимое уточнение хронологии и следующее поручение Sol](https://github.com/iliya1947/Major_Renov2/pull/3#issuecomment-6223103954). **Статус:** независимый cost/frequency audit по небольшому, выборочно собранному набору эпизодов. Не причинный эксперимент, не оценка распространённости сбоев GPT-6 в целом.

## 1. Метод ограничения выводов

В этой записи **разделяются три вещи**:
1. **Наблюдаемая проверочная работа:** известные точные commit SHA, CI runs, независимые RETURN/STOP и corrective action.
2. **Атрибутируемые потери от сбоя:** только там, где source позволяет сказать, что добавочное действие возникло именно из-за конкретной ошибки GPT-6. **Сам факт red CI или исправления нельзя автоматически считать ненужной работой.**
3. **Частота класса:** количество документированных **эпизодов в нашей целевой выборке**, а не скорость ошибок модели; одно и то же событие может давать пересекающиеся симптомы, поэтому нет «независимых» популяционных частот.

Технические CI проверки по разным commit могут быть **параллельными**, запускаться до получения результатов предыдущих проверок, выполнять разные части suite. Суммирование minutes runner **не равно** длительности работы GPT-6 либо времени пользователя.

**Не считать**:
- число пользовательских исправлений там, где известна только общая жалоба;
- исправления соседнего реального дефекта затратами исключительно от неверного oracle;
- обычные commits реализации как «ошибочные»;
- любую independent acceptance как «лишний reviewer return»;
- B/I/F как подтверждённые классы без чистого случая.

## 4. Ранжирование без фиктивной точности

### 4.1 По наблюдаемой технической цене/возвратам, в **этой** выборке

- **Quote (не классифицирован как I/F):** наибольшее установленное число последовательных CI iterations (**5 fail + 1 success**), но это process-case, а не доказанный новый class mechanism.
- **O:** **2 документированных самостоятельных технических случая**, оба потребовали сторонней диагностики/коррекции, один требовал реального browser user-path (CI был green). Это **лучше подтверждённая повторяющаяся техническая категория**, чем E или V в данном маленьком наборе, но не статистическая частота.
- **V:** **1** самостоятельный reviewer RETURN после зелёного CI, correction сохранила большую часть работы; здесь есть наиболее определённый **внешний источник вариантов** (официальный CommonMark).
- **E:** **1** отдельное причинное objection + document correction, **0 доказанных реализационных патчей вследствие false cause**.
- **G:** прямое соответствие основной жалобе пользователя — **высокая релевантность цели**, но денежный/временны́й/CI budget и число человеческих коррекций не посчитаны; нельзя объявить G дешевле E/V только из-за отсутствия GitHub метрик.

Потенциальное ранжирование **по частоте причинной ошибки GPT-6** на данных невозможно. Особенно нельзя сравнивать **время в GitHub** с **временем пользовательского чата** на одной шкале.

### 4.2 По возможности следующего **причинного пилота**, не по объявленной распространённости

- **V/CommonMark:** strongest **new external content**: official pinned conformance set → deterministic selector → project metamorphic source-editing property. Может быть реализован в обычном test environment без browser. Область узкая и историческая версия ещё не закреплена; без A/B нельзя доказать экономию.
- **O/native path:** реально отличающий браузерный observable, два исторических случая O в нашем наборе; browser runner дороже/уже, и корректный oracle выбирается отдельно.
- **G:** наиболее близок к требованию пользователя, но `completion contract pilot v2` требует **независимого автора контракта/runner**, недоступен в одиночном чате. Важно **не заменить G дешевизной технических тестов V**.
- **E:** внешние causal traces помогают независимому reviewer, но нового общего pre-action semantic gate не найдено.
- **C2/I/F:** отложить до появления чистого post-FAIL unjustified continuation; не строить policy-controller на недоказанной цели.

**Рекомендация как исследовательский приоритет, не приказ внедрения:** если следующая цель — **получить первое измеренное доказательство**, что независимый внешний материал сокращает собственные пропуски GPT-6, то **V/CommonMark** — наименее спекулятивный **узкий proof-of-effect candidate**. Если цель — **максимально уменьшить коррекции пользователя вне кодовых проектов**, V-результат не переносится на G автоматически; потребуется отдельная среда для G. **По абсолютной стоимости и частоте "самого дорогого класса" решение не вынесено.**

## 5. Что потребуется для корректной оценки эффекта и цены следующего вмешательства

Приоритет выбирается по **доле фактического предотвратимого ущерба**, а не по количеству сообщений об ошибках. Для сравнения необходимы:
- задачи одной категории с заранее независимым ground truth для результата;
- реально выполнимый baseline и treatment с одинаковыми ограничениями;
- фиксация стоимости не только CI/commits, но **реальных повторных действий GPT-6, времени человека и false-stop**;
- независимый evaluator, не использующий self-report GPT-6 как доказательство успеха;
- разделение `avoided false acceptance`, `avoided repeated wrong action` и `less user correction`.

**По имеющимся материалам экономия пользователя не установлена и механизм универсального повышения внимательности GPT-6 не найден.** Не менять `AGENTS.md`, PR #147/#215, CI, permissions, не инициировать Codex Code Review и не создавать новые реализации в рамках cost-аудита.
