# 2. Canonical grounded-theory purpose

Grounded theory is not simply qualitative coding of interview transcripts.

Its primary scientific target is:

**develop a conceptual explanatory theory/model grounded in systematically compared data, usually concerning a social, behavioral, interactional or temporal process.**

Typical GT questions:

- How do people move through process X?
- What conditions shape action/interaction in process X?
- How do participants respond to a recurring problem or concern?
- What process explains maintenance, adaptation, disengagement or decision-making?
- How do categories relate to form an explanatory account?

### Critical rule

A study can use grounded-theory coding techniques without being a full grounded-theory study.

For a full GT design claim, the project should show a coherent iterative architecture:

data generation ↔ coding ↔ comparison ↔ memoing ↔ theoretical sampling ↔ category development ↔ theory construction.

---

# 3. Grounded theory is a family, not one coding recipe

The main families relevant to RES-02 are:

1. classic / Glaserian grounded theory;
2. Straussian grounded theory;
3. constructivist grounded theory associated with Charmaz.

They share a recognizable core but differ in:

- epistemological assumptions;
- researcher role;
- degree of procedural structure;
- coding vocabulary;
- use of pre-existing concepts/literature;
- how theory is described as discovered/emergent vs constructed/co-constructed.

### Project rule

Do not write only "design = grounded theory".

Record the exact GT lineage when stated.

---

# 4. Shared grounded-theory core

Across the main variants, the strongest common architecture is:

1. theory-generation purpose;
2. concurrent or tightly iterative data collection and analysis;
3. constant comparison;
4. progressive abstraction from data to concepts/categories;
5. memo-writing;
6. theoretical sampling or concept-driven further data acquisition;
7. category refinement and relational integration;
8. theoretical saturation / conceptual sufficiency appropriate to the chosen lineage;
9. a final explanatory theoretical product, not only a list of themes.

Not every school uses identical terminology.

---

# 5. Constant comparative method

Constant comparison is central.

Comparisons can include:

- incident ↔ incident;
- incident ↔ code;
- code ↔ code;
- code ↔ category;
- category ↔ category;
- participant ↔ participant;
- context ↔ context;
- earlier data ↔ later data;
- confirming case ↔ disconfirming/negative case.

Purpose:

increase conceptual precision, identify properties/dimensions, reveal variation, refine relationships and direct further sampling.

### Critical boundary

Constant comparison is more than "we compared transcripts".

In full GT, comparison should affect the developing analysis and what data are sought next.

# 6. Theoretical sampling

## Definition

Theoretical sampling means:

emerging concepts/categories determine what data should be collected next, from whom, where or in what form, in order to elaborate and test the developing theory.

Canonical sequence:

initial sampling → early analysis → conceptual gap/question → sample next case/data source → compare → refine category → repeat.

## Not the same as purposive sampling

Purposive sampling:

select people/data because they are relevant to the research topic.

Theoretical sampling:

select the next people/data because the emerging theory requires a specific comparison or conceptual test.

### Example

Initial interviews suggest that long-term physical-activity maintainers differ in how they handle disruption.

A theoretical-sampling decision might deliberately recruit:

- people who maintained activity despite injury;
- people who resumed after interruption;
- people with stable routines but different social contexts;

because those cases can clarify the emerging category of adaptability.

### Rule

A fixed sample chosen entirely before analysis can support GT-informed analysis, but it weakens a claim to a fully executed GT design if no meaningful theoretical sampling was possible.

---

# 7. Memo-writing

Memoing is part of the analytic engine, not optional administration.

Memos can record:

- code definitions;
- emerging categories;
- possible category relationships;
- unresolved contradictions;
- negative cases;
- comparisons;
- theoretical hunches;
- reasons for theoretical-sampling decisions;
- shifts in interpretation;
- candidate core/central categories.

Function:

descriptive code → conceptual category → integrated theory.

### Project extraction

Record:

1. were memos used?;
2. when?;
3. what analytic role?;
4. did memos guide sampling/comparison?;
5. were diagrams/maps used?;
6. did they support theoretical integration?

# 8. Classic / Glaserian grounded theory

## 8.1 Main orientation

Classic GT emphasizes:

- emergence of concepts from data;
- minimizing forcing into a preconceived analytic frame;
- open coding followed by selective coding around a core category;
- theoretical coding to integrate categories;
- theoretical sampling;
- theoretical saturation.

## 8.2 Coding architecture

Typical Glaserian structure:

### Substantive coding

1. open coding:
   - conceptualize incidents broadly;
   - compare continuously;
   - identify candidate categories.

2. selective coding:
   - once a core category emerges, focus coding/data collection on concepts relevant to it.

### Theoretical coding

Relates substantive categories conceptually into a theory.

### Critical rule

Classic GT does not require Straussian axial coding.

Do not reject a Glaserian study because it lacks an open–axial–selective sequence.

## 8.3 Core category

A classic GT often seeks a core category that:

- accounts for substantial variation;
- relates meaningfully to other categories;
- organizes the explanatory pattern.

## 8.4 Literature boundary

Classic GT traditionally warns against allowing prior literature/theory to force the analysis prematurely.

Project interpretation:

this is a lineage-specific strategy, not a universal prohibition on reading literature before qualitative research.

The relevant extraction question is:

how was prior theory handled so it did not simply dictate the emerging categories?

# 9. Straussian grounded theory

## 9.1 Main orientation

Strauss/Corbin variants are more procedurally explicit.

Typical emphases:

- structured coding;
- category properties/dimensions;
- conditions;
- actions/interactions;
- consequences;
- explicit relational analysis.

## 9.2 Coding architecture

Classic Straussian vocabulary:

1. open coding;
2. axial coding;
3. selective coding.

Later Corbin/Strauss texts use more flexible terminology, with theoretical integration replacing some earlier selective-coding language.

## 9.3 Axial coding

Axial coding reconnects fractured data by examining relationships among:

- category;
- conditions;
- context;
- actions/interactions;
- consequences;
- properties/dimensions.

The coding paradigm is a Straussian tool.

### Critical rule

Open → axial → selective is not the universal definition of grounded theory.

It identifies a Straussian-style coding architecture.

## 9.4 Induction/deduction

Straussian GT historically permits a more explicit interplay of:

- induction;
- deduction;
- checking emerging relational propositions through later data collection.

This is one reason it should not be flattened into classic Glaserian GT.

---

# 10. Constructivist grounded theory

## 10.1 Main orientation

Charmaz explicitly rejects the idea that data and theory are simply discovered as objective entities independent of the researcher.

Constructivist GT assumes:

data and analyses are constructed through interactions among participants, researchers, contexts and interpretive practices.

The final theory is:

an interpretive rendering of the studied world, not an exact mirror of it.

## 10.2 Researcher role

Researcher positioning and reflexivity matter explicitly.

Record:

- researcher background;
- relationship to participants;
- prior theoretical commitments;
- interpretive decisions;
- social/contextual position.

## 10.3 Coding architecture

Typical Charmaz sequence:

1. initial coding;
2. focused coding;
3. theoretical integration / theoretical coding as appropriate.

Initial coding:
- stays close to data;
- may use active/process-oriented codes.

Focused coding:
- selects analytically significant/recurrent initial codes;
- tests and refines them across data.

### Rule

Constructivist GT does not require Straussian axial coding.

Charmaz treats axial coding as an available strategy rather than a mandatory universal step.

## 10.4 Theory as construction

The constructivist position preserves grounding in data while acknowledging:

- researcher interpretation;
- context;
- co-construction;
- multiple possible analytic renderings.

# 12. Coding is not the design

Grounded-theory coding procedures can be borrowed for:

- qualitative description;
- case study;
- implementation research;
- mixed-methods qualitative components;
- secondary qualitative analysis.

Therefore:

"we used open coding" does not equal a grounded-theory study.

Likewise:

"we used constant comparison" does not automatically establish full GT.

A full GT claim should be evaluated on the whole architecture.

---

# 13. Full GT vs thematic model / GT-informed analysis

## Stronger full-GT pattern

A study is much more defensibly classified as full GT when it includes:

1. explicit theory/process-generation question;
2. iterative data collection and analysis;
3. constant comparison;
4. memo-writing;
5. concept/category development;
6. theoretical sampling or a defensible concept-driven equivalent;
7. category saturation/conceptual sufficiency;
8. relational integration;
9. explanatory theory/process model.

## Weaker / GT-informed pattern

Examples:

- all interviews collected before analysis;
- no theoretical sampling;
- coding only;
- final result is a list of themes;
- no relational integration;
- no explanatory process/theory.

Better classification:

qualitative study using grounded-theory-informed analytic techniques

rather than automatically:

grounded-theory design.

### Important nuance

GT methods can legitimately be used as analytic tools without completing a full GT study.

Classification must match the claim actually supported.

# 14. Categories, properties, dimensions and core processes

Grounded theory moves toward conceptual abstraction.

## Code

A label for an incident/action/meaning.

## Category

A higher-order concept that groups and explains related patterns.

## Properties

Characteristics of a category.

## Dimensions

Variation along properties.

## Core / central category

In traditions that use the concept:

the main organizing category/process linking major parts of the theory.

## Theory

Not merely several themes connected with arrows.

A grounded theory should explain, to the degree appropriate for its lineage:

- process;
- relationships;
- conditions;
- variation;
- action/interaction;
- consequences.

# 15. Theoretical saturation

Theoretical saturation in its original GT sense is not participants repeating the same phrases.

It concerns theoretical categories.

Canonical criterion:

additional theoretically directed data no longer produce important new properties, dimensions, relationships or theoretical insights for the relevant categories.

### Distinguish

- data repetition;
- code saturation;
- thematic saturation;
- theoretical saturation.

These are not interchangeable.

## Sampling consequence

Because theoretical sampling depends on emerging categories:

the final GT sample size generally cannot be known exactly in advance.

A protocol can give an anticipated range, but actual stopping should follow conceptual development where methodology allows.

---

# 16. Saturation vs sufficiency

For GT, theoretical saturation remains historically and methodologically central.

Reviewers should inspect:

1. what category was being saturated?;
2. what properties remained underdeveloped?;
3. what theoretical-sampling steps were taken?;
4. were negative/contrasting cases sought?;
5. did later data stop changing the theory?;
6. or did researchers merely stop because recruitment/time ended?

### Project rule

Do not accept "saturation was reached" as sufficient evidence by itself.

Require operational detail.

---

# 17. Negative cases and variation

A developing theory becomes stronger when researchers deliberately seek:

- deviant cases;
- contrasting contexts;
- cases at different stages of a process;
- participants who challenge an emerging explanation.

The goal is not statistical representativeness.

The goal is:

test, refine and delimit the conceptual explanation.

---

# 18. Data sources in grounded theory

Interviews are common, but GT is not interview-only.

Possible sources:

- interviews;
- observations;
- field notes;
- documents;
- diaries;
- digital traces;
- records;
- existing datasets;
- combinations.

### Rule

Data-source choice should serve conceptual development.

If a category concerns how training plans are actually modified in practice, observation or training logs may theoretically sample the process better than another abstract interview.

---

# 19. Longitudinal grounded theory

GT can be longitudinal when the target process unfolds over time.

Useful for:

- exercise adoption → adherence → lapse → re-engagement;
- injury → rehabilitation → return;
- novice → experienced lifter identity;
- training burnout → disengagement → recovery;
- long-term adaptation to chronic-disease exercise.

Longitudinal data can improve process theory because transitions are observed rather than all reconstructed retrospectively.

### Boundary

Repeated interviews alone do not make a study grounded theory.

GT still requires conceptual iteration and theory development.

---

# 20. What grounded-theory evidence can establish

GT can strongly support:

- conceptual explanations of social/behavioral processes;
- categories and relationships grounded in participant/context data;
- conditions under which a process changes;
- action/interaction strategies;
- process stages/trajectories;
- context-sensitive explanatory models;
- hypotheses for later quantitative/experimental testing.

It can identify candidate mechanisms at behavioral/social level.

---

# 21. What grounded-theory evidence cannot establish by itself

GT alone does not estimate:

- population prevalence;
- incidence;
- risk;
- average causal effect;
- intervention efficacy;
- biological mediation;
- diagnostic accuracy;
- prediction calibration/discrimination.

### Critical causal boundary

A grounded theory may explain how participants perceive that confidence, enjoyment and social support interact in exercise maintenance.

It does not by itself establish the causal effect size of confidence on adherence.

# 22. Fitness / exercise crosswalk

| Question | Correct GT interpretation |
|---|---|
| How do people maintain regular physical activity for years? | constructivist GT candidate if theory of maintenance is developed iteratively |
| How do people move from adoption to adherence, lapse and return? | longitudinal GT candidate |
| What process explains dropout from resistance training? | GT if process/theory generation is target |
| Which barriers are most commonly reported? | not necessarily GT; often qualitative description |
| What is it like to train after injury? | phenomenology, not automatically GT |
| How do gym cultures shape behavior? | ethnography may fit better unless process theory is target |
| Does social support cause adherence? | causal-effect question, not resolved by GT |
| What process links identity, enjoyment and routine in long-term activity? | GT candidate |
| Interviews + open/axial/selective coding + theoretical sampling | Straussian GT pattern |
| Initial/focused coding + memoing + theoretical sampling + co-constructed theory | constructivist GT pattern |
| Open/selective/theoretical coding around core category | classic/Glaserian GT pattern |

## Current exercise exemplar

A 2026 constructivist grounded-theory study of long-term physical-activity maintainers used in-depth interviews and produced an interconnected conceptual model around enjoyment, adaptability, well-being, priority, organization and community.

Project interpretation:

the GT claim depends not merely on categories/model, but on whether iterative comparison, sampling, memoing and theoretical development were actually implemented and reported.

# 24. Do-not-confuse matrix

| Do not confuse | Why |
|---|---|
| grounded-theory coding vs grounded-theory design | coding techniques can be borrowed elsewhere |
| open/axial/selective coding vs all GT | mainly Straussian architecture |
| theoretical sampling vs purposive sampling | theoretical sampling follows emerging concepts |
| theoretical saturation vs repeated answers | saturation concerns category/theory development |
| fixed sample plan vs theoretical sampling | GT ideally lets analysis redirect sampling |
| themes vs theory | themes need relational/explanatory integration |
| conceptual diagram vs grounded theory | arrows alone do not establish GT methodology |
| core category vs most frequent code | conceptual centrality is not frequency |
| memoing vs field notes only | analytic memos develop concepts/relationships |
| emergence vs researcher absence | all GT involves analytic decisions; constructivist GT makes this explicit |
| Glaserian vs Straussian | different coding/integration assumptions |
| Straussian vs Charmaz | axial paradigm is not Charmaz requirement |
| GT process explanation vs causal effect | conceptual explanation does not estimate causal magnitude |
| GT sample size vs statistical power | different stopping logic |
| qualitative theory vs universal theory | GT is often context-bound/substantive |
