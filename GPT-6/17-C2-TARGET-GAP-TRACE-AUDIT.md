## 1. Заранее зафиксированный необходимый trace

Проверка Sol требует одновременно:

1. существует **внешний executable FAIL**, а не субъективное замечание или зелёный CI;
2. GPT-6 **имела этот FAIL в доступном контексте** до действия;
3. до independent Sol/Codex разрешения модель сделала **следующий write/action**;
4. следующий action **не был обоснованным исправлением установленной причины**;
5. evidence показывает продолжение неверной/неподтверждённой стратегии;
6. установлена конкретная дополнительная стоимость — лишний commit/CI/возврат reviewer/неверная правка.

**Отдельно:** для доказательства **I** нужна временна́я последовательность существенного опровержения стратегии → продолжение именно этой стратегии. Для **F** нужен **заранее обоснованный** threshold STOP → его пропуск. Ни количество red CI, ни позднейший успешный рефакторинг сами по себе этого не доказывают.

## 4. Что можно и нельзя измерить

**Установленные минимальные затраты в quote случае:** как минимум один красный `checks` run на `fdf8160`, последующий успешный `checks` run на `4122e08`, три новых commits между известными heads; также было независимое обсуждение в #147. Но **нет независимого вывода, что хоть один конкретный пост-fail commit необоснован**, поэтому нельзя объявлять эти затраты предотвращаемыми C2.

**Нельзя утверждать:** что GPT-6 продолжала неправильную стратегию после получения опровержения; что обязательный STOP существовал и был нарушен; что новый C2 сократил бы число действительных ошибочных действий. Для I/F чистого якоря здесь всё ещё нет.

## 5. Решение для C2

**Текущий обоснованный статус:** `C2 target gap NOT YET ESTABLISHED`, `I and F NOT YET CONFIRMED`.

**Не запускать C2 pilot, не вводить branch write guards или новые универсальные инструкции.** Наличие конкретного FAIL без доказательства неверной реакции на него — недостаточная причинная основа для новой инфраструктуры.

**Если обсуждение продолжится:** нужен либо полный dated commit-by-commit + model-visible-message trace между прежними quote failing heads, либо другой документированный случай, где впервые обнаружено **именно ошибочное продолжение** после уже доставленного FAIL. Это не просьба пользователю вручную восстанавливать историю и не обещание несуществующих проверок. До получения данных удерживать negative/uncertain result.
