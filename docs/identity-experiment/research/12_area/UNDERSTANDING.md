# A1 №12 — понимание после новой первичной картографии

**Статус:** новая A1 завершена 15.10.2026 после полного удаления предыдущей попытки.

## Что удалось установить на уровне карты

1. **Prompt engineering и instruction following нельзя смешивать.** Первое проектирует входные инструкции/контекст; второе описывает способность конкретной обученной модели понимать и выполнять их.

2. **Не всё управление поведением находится в тексте prompt.** Часть поведения определяется обучением модели, hierarchy/authority, runtime constraints, schemas, permissions, tool orchestration и product-level context.

3. **Persistent project instructions — отдельная подзадача.** Для нашего будущего эксперимента важно исследовать не только wording одного запроса, а долговременное взаимодействие стабильных project rules с history, files и меняющимся опытом.

4. **Persona prompting нельзя принимать за путь к формированию индивидуальности.** Это заранее заданное описание роли/характера; литература показывает, что даже как способ повышения task performance persona не является универсально полезной.

5. **Prompt behavior необходимо рассматривать как нестабильное относительно context и model version.** На результат влияют wording, order, position, demonstrations, history, language и конкретный model snapshot.

6. **Long context не равен надёжной памяти.** Наличие инструкции или факта в большом контексте не гарантирует одинакового использования независимо от позиции и окружения.

7. **Examples — самостоятельный источник steering.** Они могут задавать поведение наряду с explicit rules, поэтому в будущем нужно отдельно исследовать их влияние и возможный конфликт с постоянными инструкциями.

8. **Self-critique/self-correction — отдельная спорная ветвь.** Нельзя автоматически переносить успех итеративного исправления задач на способность модели надёжно переосмысливать собственный опыт.

9. **Evaluation — часть самого prompt engineering процесса.** Один удачный диалог не показывает robustness; нужны проверки paraphrase, history, conflicts, edge cases, repeated runs, model versions и languages.

10. **Automatic prompt optimization не заменяет понимание задачи.** Она оптимизирует заданный objective/eval signal и потому сама создаёт вопросы generalization и overfitting.

11. **Для нашей задачи особенно важна граница stable rules ↔ evolving experience.** Если изменяемое содержание заранее зашить в persistent instruction, это будет программированием личности; если же все правила сделать изменяемыми, потеряется устойчивый процесс эксперимента. Это пока только направление будущего исследования, не готовое решение.

## Результат

Создана новая карта из **166 вопросов** по 20 блокам. Старые 350 вопросов не использованы как действующий результат.

На этом проходе выполнено широкое ориентирование по обзорам, abstracts и актуальной официальной документации. Глубокого исследования отдельных вопросов A1 не проводила.
