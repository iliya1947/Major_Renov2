# RES-02 / PASS-06F6 — HCD/UCD/co-design/Person-Based Approach boundary and study structures

Статус: **COMPLETE — HCD/UCD/PBA TAXONOMY ESTABLISHED; CO-DESIGN GOVERNANCE BLOCKER IDENTIFIED**

Topic: RES-02 — Study designs / what they answer

## Purpose

Этот PASS разбирает границы между:

- Human-Centred Design (HCD);
- User-Centred Design (UCD);
- participatory design;
- co-design;
- co-production/co-creation;
- Design Thinking;
- Person-Based Approach (PBA).

Главный вопрос:

> что является design/development framework, что participatory process/governance layer, что intervention-development approach, а что лишь набором методов — и какие claims допустимы после каждого типа работы.

---

# 1. Final routing decision

Canonical project classes:

1. **HCD/UCD**  
   → **DESIGN / DEVELOPMENT FRAMEWORK**

2. **Participatory Design / Co-design**  
   → **PARTICIPATORY DESIGN PROCESS + GOVERNANCE LAYER**

3. **Co-production / Co-creation**  
   → **BROAD PARTICIPATORY GOVERNANCE / DEVELOPMENT LABEL; EXACT ENACTED AUTHORITY MUST BE STORED**

4. **Design Thinking**  
   → **INNOVATION / PROBLEM-SOLVING PROCESS FAMILY, NOT AN ATOMIC RESEARCH DESIGN**

5. **Person-Based Approach (PBA)**  
   → **HEALTH-INTERVENTION DEVELOPMENT APPROACH / METHODOLOGY**

None of these labels automatically determine:

- causal design;
- mixed-methods design;
- qualitative methodology;
- quantitative design;
- effectiveness evidence.

Embedded empirical designs must be preserved separately.

# 2. HCD/UCD — current ISO status

Current authoritative standard:

**ISO 9241-210:2019, Edition 2**

ISO confirms that this edition was reviewed and confirmed in **2025** and therefore remains current.

Project route:

**HCD_UCD_FRAMEWORK**

ISO 9241-210 addresses human-centred design principles and activities throughout the life cycle of interactive systems.

### Core HCD principles

The current ISO lineage retains six core principles:

1. design is based on explicit understanding of users, tasks and environments;
2. users are involved throughout design and development;
3. design is driven/refined by user-centred evaluation;
4. process is iterative;
5. design addresses the whole user experience;
6. design team includes multidisciplinary skills and perspectives.

### Core iterative activities

1. understand and specify context of use;
2. specify user requirements;
3. produce design solutions;
4. evaluate designs against requirements.

These activities iterate rather than form one rigid linear sequence.

### Critical rule

ISO HCD is **not a study design**.

It is a design-process framework that can contain many empirical methods.

# 3. HCD vs UCD

In practice HCD and UCD overlap heavily.

Project distinction:

## HUMAN-CENTRED DESIGN

Broader framing:

- users;
- other affected stakeholders;
- human factors;
- ergonomics;
- whole user experience;
- context of use;
- lifecycle.

## USER-CENTRED DESIGN

Typically narrower emphasis on intended users and their interaction with the designed system/product.

### Project rule

Do not invent a hard universal separation where authors use the terms interchangeably.

Store:

- AUTHOR_LABEL;
- exact design activities;
- stakeholder groups;
- context-of-use work;
- evaluation method;
- governance depth.

Preferred canonical umbrella:

**HCD/UCD**

unless the source explicitly requires a narrower classification.

# 5. User requirements

HCD requires transition:

user/context evidence  
→ user needs  
→ explicit user requirements  
→ design requirements  
→ design solution.

### Critical rule

Do not collapse:

- user desire;
- user need;
- requirement;
- design feature.

A stakeholder request is evidence, not automatically the final requirement.

Requirements may conflict and require prioritisation.

# 6. Iterative design

Canonical cycle:

context  
→ requirements  
→ design solution/prototype  
→ user-centred evaluation  
→ refinement.

Iteration may alter:

- requirements;
- workflow;
- interface;
- content;
- delivery;
- accessibility;
- support;
- technical architecture.

### Critical rule

Iteration alone does not prove HCD quality.

The redesign should be traceable to:

- user/context evidence;
- evaluation;
- explicit rationale.

Possible artifact maturity:

- concept;

# 8. Usability

Current ISO 9241-11:2018 remains current after ISO confirmation in 2023.

Usability is defined around specified users achieving specified goals with:

- effectiveness;
- efficiency;
- satisfaction;

in a specified context of use.

### Project rule

Usability is an **outcome of use**, not a synonym for:

- acceptability;
- engagement;
- clinical efficacy;
- behavior change;
- implementation success.

---

# 9. Usability evaluation

Possible methods:

- task-based usability testing;
- think-aloud;
- observation;
- heuristic inspection;
- cognitive walkthrough;
- questionnaires;
- interviews;
- field testing;
- usage/log analysis.

### Critical rule

Each method answers different questions.

Example:

SUS score may support perceived usability.

It does not by itself establish:

- task accuracy;
- safety;
- long-term adherence;
- health outcome.

# 10. HCD proximal outcomes in health

Current 2025 health review highlights prominent proximal HCD targets:

- usability;
- user burden;
- contextual appropriateness;
- engagement.

These are relevant implementation/design outcomes.

### Critical boundary

They remain distinct from:

- clinical effectiveness;
- behavioural effectiveness;
- population health effect.

---

# 11. HCD vs causal/effectiveness research

HCD can improve:

- interface;
- fit;
- accessibility;
- workflow;
- uptake potential;
- contextual appropriateness.

But HCD label does not identify:

- treatment effect;
- causal behavior change;
- clinical benefit.

### Project representation

HCD framework  
+ artifact/version  
+ empirical evaluation design  
+ exact outcome.

If a later RCT evaluates the HCD-developed intervention:

RCT owns causal effectiveness inference.

---

# 12. Participatory Design

Participatory Design gives intended users/stakeholders an active role in shaping design.

Possible participation:

- identifying problems;
- generating ideas;
- selecting priorities;
- prototyping;
- testing;
- deciding final features;
- implementation planning.

### Project classification

**PARTICIPATORY_DESIGN_PROCESS**

### Critical rule

“Users were interviewed” does not automatically mean participatory design.

Participation requires influence on the design process, not merely data provision.

---

# 13. Co-design

Current public-health literature confirms that **co-design is heterogeneous**.

The 2025 systematic review found:

- many studies did not define co-design;
- frameworks varied;
- participant roles ranged from informants to actual co-designers;
- prototype development/testing was not universal.

### Project classification

**CO_DESIGN_PROCESS + GOVERNANCE**

Do not classify from author label alone.

Mandatory fields:

1. who participated;
2. at which stages;
3. what decisions participants could influence;
4. what decisions remained researcher-controlled;
5. whether priorities were shared;
6. whether prototypes were built;
7. whether participants evaluated prototypes;
8. whether final decisions were shared;
9. compensation;
10. accessibility;
11. power/conflict handling.

---

# 14. Participation-depth spectrum

Project routing should distinguish at least:

1. **INFORM**
   - participants receive information.

2. **CONSULT**
   - researchers collect views.

3. **INVOLVE**
   - repeated participant input influences development.

4. **COLLABORATE / CO-DESIGN**
   - participants jointly generate/refine design decisions.

5. **SHARED_AUTHORITY / CO-PRODUCTION**
   - meaningful shared decision power extends across substantial parts of development/implementation/governance.

### Critical rule

This is a project routing spectrum, not a claim that one universal published ladder governs all co-design traditions.

---

# 15. Co-design vs consultation

Consultation:

research team asks  
→ participants respond  
→ research team decides.

Co-design:

participants have material influence on:

- problem definition;
- priorities;
- solutions;
- prototypes;
- refinement;

to a degree that should be explicitly documented.

### Critical rule

Focus groups followed by researcher-only intervention design should not automatically be coded as full co-design.

---

# 16. Co-production / co-creation boundary

Current health literature shows substantial terminological overlap between:

- co-design;
- co-creation;
- co-production.

Many studies do not clearly define which model they use.

### Project decision

Do not enforce a universal semantic hierarchy unsupported by the paper.

Store:

- AUTHOR_LABEL;
- enacted activities;
- governance depth;
- decision authority;
- lifecycle stages.

### Preferred routing

If shared authority extends beyond design into:

- implementation;
- delivery;
- evaluation;
- sustainability;
- governance,

route as broader:

**CO_PRODUCTION / SHARED_GOVERNANCE**

rather than design-only co-design.

# 17. Experience-Based Co-Design (EBCD)

EBCD is a specific health-service improvement/design lineage.

Core architecture commonly includes:

- collecting service-user/staff experiences;
- identifying key experience/touch points;
- bringing groups together;
- joint prioritisation;
- co-design working groups;
- service improvement.

Current methodological work describes EBCD as a participatory methodology/process and emphasises:

- facilitation;
- power;
- participant involvement;
- transparent adaptation.

### Critical rule

EBCD is not equivalent to every form of co-design.

Project route:

**EBCD_SUBTYPE / SPECIFIC CO-DESIGN ARCHITECTURE**

# 18. Evidence-informed Experience-Based Co-Design (E2CD)

Current 2024 E2CD framework explicitly attempts to integrate:

- research evidence;
- lived experience;
- shared priority setting;
- co-design.

### Project route

E2CD is a specific framework/subtype under the co-design family.

It does not create:

- causal-effect evidence;

# 19. Design Thinking

Design Thinking is widely used as an innovation/problem-solving approach.

Common recurring activities include variants of:

- empathise/understand;
- define;
- ideate;
- prototype;
- test.

But health literature shows substantial variability in:

- terminology;
- process;
- reporting;
- methodological rigor.

A 2025 patient-safety scoping review reported major under-reporting of study design and data procedures.

### Project classification

**DESIGN_THINKING_PROCESS_FAMILY**

not:

- atomic study design;
- evidence-quality shortcut.

### Critical rule

Do not infer HCD rigor merely because a study says “Design Thinking”.

Record actual methods and decision processes.

# 20. Person-Based Approach (PBA)

PBA is a distinctive intervention-development approach developed in health behaviour-change research.

Current 2025 scoping review includes **239 papers** and confirms broad use in:

- digital interventions;
- hybrid interventions;
- offline interventions;
- public health;
- healthcare;
- community settings.

Project route:

**PERSON_BASED_APPROACH**

Project class:

**HEALTH INTERVENTION-DEVELOPMENT APPROACH / METHODOLOGY**

---

# 21. PBA core architecture

Original PBA has two defining elements.

## 1. Iterative qualitative research throughout development

Research with target users can occur during:

- initial planning;
- intervention development;
- optimisation;
- feasibility;
- implementation.

The aim goes beyond simple satisfaction measurement.

It seeks understanding of:

- psychosocial context;
- user perspectives;
- barriers;
- facilitators;
- likely reactions to behaviour-change components;
- engagement.

## 2. Guiding Principles

Guiding Principles translate person-based evidence into:

- key user context/features;
- design objectives;
- intervention features.

### Canonical chain

USER_CONTEXT  
→ KEY_ISSUE  
→ DESIGN_OBJECTIVE  
→ INTERVENTION_FEATURE.

---

# 22. PBA + evidence + theory

Modern PBA is not intended to replace:

- evidence-based intervention development;
- behavioural theory.

Current literature explicitly treats PBA as a way to combine:

- evidence;
- theory;
- person-based research.

### Project rule

Store all three separately:

1. EVIDENCE_INPUT;
2. THEORY_INPUT;
3. PERSON_BASED_INPUT.

### Critical rule

A user-preferred feature should not automatically override:

- safety;
- established evidence;
- intervention mechanism;

without an explicit design decision.

# 23. PBA Guiding Principles

Current official PBA guidance defines Guiding Principles around:

1. characteristics/context likely to affect engagement;
2. key design objectives;
3. intervention features intended to achieve those objectives.

They should be:

- target-user specific;
- engagement focused;
- revisable throughout development.

### Project fields

1. USER_CONTEXT;
2. DESIGN_OBJECTIVE;
3. KEY_FEATURE;
4. SOURCE_EVIDENCE;
5. VERSION;
6. REVISION_TRIGGER.

# 24. PBA optimisation

Common methods include:

- in-depth interviews;
- think-aloud interviews;
- iterative prototype feedback;
- usability observation;
- thematic/qualitative analysis;
- stakeholder consultation.

### Critical rule

PBA is not defined by one interview method.

The defining feature is the systematic person-based intervention-development logic.

---

# 25. PBA vs HCD/UCD

Overlap:

- user needs;
- context;
- iteration;
- prototype/refinement;
- user feedback.

PBA distinctive emphasis:

- health behaviour-change intervention development;
- psychosocial context;
- engagement with intervention content/behaviour-change elements;
- Guiding Principles;
- explicit combination of evidence/theory/person perspective.

HCD distinctive emphasis:

- human–system interaction;
- context of use;
- requirements;
- usability/UX;
- lifecycle design.

### Project rule

PBA and HCD can coexist.

Do not automatically merge them.

---

# 26. PBA vs co-design

PBA can involve users deeply without requiring shared design authority.

Example:

users provide rich think-aloud feedback  
→ researchers interpret and modify intervention.

This can be strong PBA but not full co-design.

Co-design requires material participant influence on design decisions.

### Critical rule

User-centred ≠ co-designed.

---

# 27. PBA vs mixed methods

PBA may use:

- qualitative-only development;
- surveys;
- mixed methods.

But PBA is not mixed methods by definition.

Project representation:

PBA development framework  
+ exact empirical design(s)  
+ MMR route only if E-branch integration criteria are met.

---

# 28. PBA vs Behaviour Change Wheel / COM-B

Current 2026 physical-activity work directly combines:

- PBA;
- Behaviour Change Wheel;
- COM-B/BCT logic;
- think-aloud optimisation.

### Project rule

Treat them as complementary layers:

PBA  
→ person/context + engagement.

BCW/COM-B  
→ behavioural diagnosis/intervention functions.

Neither replaces the other.

---

# 29. Acceptability, feasibility, usability, engagement, effectiveness

These must remain distinct.

## ACCEPTABILITY

Whether the intervention is perceived as appropriate/satisfactory/tolerable.

## FEASIBILITY

Whether it can practically be delivered/used/tested.

## USABILITY

Effectiveness + efficiency + satisfaction for specified user goals in context of use.

## ENGAGEMENT

Behavioural and/or experiential involvement with intervention.

## BEHAVIOURAL EFFECTIVENESS

Whether target behaviour changes.

## CLINICAL EFFECTIVENESS

Whether relevant health outcomes improve.

### Critical rule

Good usability/acceptability can be necessary for effectiveness but does not prove effectiveness.

# 30. Current sport / exercise / rehabilitation relevance

Direct current applications strongly verify relevance.

## Exercise maintenance after falls-prevention programmes — 2026

A three-stage co-design process with:

- older adults;
- rehabilitation professionals;
- service providers;

developed an exercise-maintenance intervention.

Final product remained ready for later feasibility/acceptability testing.

### Lesson

Co-design output ≠ completed effectiveness evidence.

## Spinal cord injury sedentary-behaviour intervention — 2026

Current rehabilitation work combines:

- Behaviour Change Wheel;
- co-design;
- SCI stakeholder input.

### Lesson

BCW and co-design are separate layers.

## Stroke physical-activity maintenance — 2026

A mixed-method study uses:

- focus groups;
- co-production workshops;
- expert review;
- prototyping.

### Lesson

Mixed methods + co-design + intervention development can coexist.

## PERFORM exercise-based rehabilitation — 2025

Personalised exercise-based rehabilitation/self-management intervention for people with multiple long-term conditions was developed through co-design.

### Lesson

Co-design has direct exercise-rehabilitation relevance.

## PBA physical-activity intervention — 2026

Physical-activity promotion for older Chinese adults used:

- PBA;
- BCW;
- Guiding Principles;
- intervention planning table;
- logic model;
- think-aloud optimisation.

The authors explicitly state that further feasibility/acceptability/effectiveness evaluation is needed.

### Lesson

PBA development success ≠ established intervention effectiveness.

# 31. Power and equity

HCD/co-design can still reproduce exclusion if:

- only easy-to-recruit users participate;
- accessibility needs are missed;
- professionals dominate decisions;
- participant feedback is selectively adopted;
- compensation is absent;
- digital access determines who participates.

### Project fields

1. participant selection;
2. excluded groups;
3. accessibility accommodations;
4. compensation;
5. decision rights;
6. conflict resolution;
7. facilitator role;
8. whose input was rejected;
9. reason for rejection;
10. equity implications.

### Critical rule

Presence of “lived experience” participants does not prove shared power.

# 32. Quality architecture

## Q1 — Context/user understanding

- target users clear;
- tasks/goals/environment clear;
- underserved users considered;
- user diversity adequate.

## Q2 — Requirements/design traceability

- user evidence → requirement;
- requirement → feature;
- feature → evaluation.

## Q3 — Iteration quality

- versions documented;
- feedback linked to redesign;
- rejected feedback recorded;
- stopping rationale.

## Q4 — Participation/governance

- participant role explicit;
- decision authority explicit;
- power/facilitation addressed;
- accessibility/compensation addressed.

## Q5 — Method quality

- interviews/qualitative work appropriately conducted;
- usability testing fit for claim;
- quantitative measures valid;
- mixed-method integration explicit where applicable.

## Q6 — Outcome calibration

- usability ≠ acceptability;
- acceptability ≠ effectiveness;
- engagement ≠ adherence;
- prototype response ≠ clinical benefit.

## Q7 — PBA fidelity

- person-based qualitative work;
- Guiding Principles;
- evidence/theory/person integration;
- iterative optimisation.

## Q8 — Reporting/provenance

- framework named;
- version;
- artifact history;
- stakeholder role;
- decision log;
- software/AI provenance.

# 34. Do-not-confuse matrix

| Do not confuse | Correct separation |
|---|---|
| HCD/UCD vs study design | development framework vs empirical design |
| HCD vs co-design | user-centred framework vs shared participatory design process |
| user research vs co-design | informing design vs sharing design decisions |
| co-design vs consultation | collaborative decision influence vs researcher-owned decisions |
| co-design vs co-production | design-focused participation vs potentially broader shared lifecycle governance |
| Design Thinking vs HCD rigor | innovation process label vs documented HCD practice |
| prototype approval vs usability | subjective approval vs context-specific use performance |
| usability vs acceptability | use effectiveness/efficiency/satisfaction vs perceived appropriateness |
| usability vs effectiveness | interaction quality vs behavioural/clinical outcome |
| PBA vs HCD | behaviour-change intervention approach vs human-system design framework |
| PBA vs co-design | person-centred qualitative development vs shared design authority |
| PBA vs BCW | person/engagement logic vs behaviour-system diagnosis/intervention functions |
| PBA vs mixed methods | development approach vs QUAL–QUAN integration |
| lived-experience participation vs shared power | presence vs decision authority |
| co-design label vs enacted co-design | author terminology vs actual governance/process |

# 35. Current unresolved blocker

HCD/UCD taxonomy is sufficiently established.

PBA taxonomy is sufficiently established for current RES-02 routing and will be re-used in the later intervention-development framework crosswalk.

However **co-design / participatory design / co-production / EBCD remains too heterogeneous to treat as closed after only a boundary section**.

Current evidence shows:

- definitions are frequently missing;
- participant roles vary substantially;
- co-design and consultation are often conflated;
- co-design/co-production terminology overlaps;
- EBCD is a more specific participatory lineage;
- power and final decision authority are methodologically important.

Therefore a dedicated narrow follow-up is required.
