# 20. Memory M1 — критерии причинной атрибуции и проверка исторических кандидатов

**GPT-6 · 2026-10-17.** Независимое исследование **только влияния долговременной cross-chat Memory ChatGPT на ошибки GPT-6** по [bounded-заданию GPT-5.6 Sol](https://github.com/iliya1947/Major_Renov2/pull/3#issuecomment-6235339849). Владелец [заморозил тестовую/A-B ветку](https://github.com/iliya1947/Major_Renov2/pull/3#issuecomment-6235031263); она здесь **не разрабатывается и не обсуждается как следующий шаг**.

**Вердикт M1: ни одного исторического эпизода, для которого вклад долгосрочной Memory доказан или достаточно обоснован как `likely contributed`, пока НЕ установлено.** Несколько эпизодов совместимы с таким влиянием, но те же наблюдения имеют конкретные альтернативные источники. Не путать отсутствие атрибуции с доказательством, что Memory никогда не влияет.

## 1. Что подтверждают внешние источники, а чего они НЕ подтверждают

- [OpenAI Help — Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt): при включённой Memory релевантный контекст может поступать из прошлых чатов и других источников, причём система выбирает существенные сведения; не сохраняет буквально всё. **Custom instructions, files/Library и подключённые приложения могут быть собственными источниками контекста**; сами по себе они не доказывают cross-chat retrieval. UI Sources могут отображать некоторые источники, но **не гарантируют исчерпывающего причинного trace**.
- [OpenAI, Dreaming, 2026-06-04](https://openai.com/index/chatgpt-memory-dreaming/): прежние механизмы могли давать устаревший/неверный/нерелевантный контекст; обновлённая архитектура направлена на freshness, relevance и correctness. Это **описание возможности и цели архитектуры**, а не evidence по конкретной GPT-6 ошибке пользователя.

Ни одна из этих публикаций не предоставляет нам логов, какие именно memories, source excerpts или retrieval outputs были вставлены **перед историческим ответом** GPT-6. Не выводить это из текущего состояния Memory summary или нынешнего recall API.

## 2. Причинная цепочка, которую необходимо различать

```text
S — прошлый факт/правило существует в отдельном источнике
     ↓ НЕ следует автоматически
R — этот источник действительно был извлечён/передан модели в конкретный ход
     ↓ НЕ следует автоматически
U — GPT-6 реально использовала его для определённого вывода или действия
     ↓ НЕ следует автоматически
E — это использование, а не другой доступный сигнал, внесло вклад в ошибку
```

**Из S нельзя вывести R; из R нельзя вывести U; из U нельзя без альтернатив вывести E.**

**Различать источники до атрибуции:**

1. **Cross-chat persistent Memory:** автоматически выбранный прошлый контекст/синтез из других диалогов.
2. **Текущий чат:** включая пользовательские цитаты «вот прошлое сообщение», инструкции в начале текущей беседы, контекст, составленный GPT-6 в уже текущем ответе.
3. **Проектные/пользовательские инструкции:** в том числе установленный `AGENTS.md` как внешний репозиторный документ, `Инструкции проекта.md` и `Пользовательские инструкции.md`, когда они доступны текущему разговору.
4. **Текущее чтение инструментом:** GitHub PR, files, docs, search, явное восстановление старого чата через персональный поиск. **Это отдельный наблюдаемый канал**; «знает из прошлого» не эквивалентно неявной Memory.
5. **Генерация без источника:** модель могла правдоподобно угадать, шаблонно дополнить или просто проигнорировать явно поставленную задачу. Внешне похожая деталь не гарантирует никакого retrieval.

**Исторические события требуют источников, действовавших в момент события.** Сегодняшнее извлечение старого факта в исследовательских целях **не** доказывает, что 12–15 октября та же память поступала модели.

## 3. Операционная observational evidence hierarchy

| Заключение | Минимально требуемая наблюдаемая основа | Что НЕ достаточно |
| --- | --- | --- |
| **MEMORY LIKELY CONTRIBUTED** | (a) датированный, специфичный past-chat detail/старое правило; (b) его *характерный* след в позднем ошибочном действии; (c) подтверждено, что на момент действия он **не был уже** в явном текущем запросе, в цитируемой пользователем истории, актуальных инструкциях, tool/PR/file context; (d) есть обоснованная временная связь **до** ошибки и конфликт с более свежим релевантным условием; (e) интерпретация как Memory вносит реальную добавочную объяснительную силу сравнительно с альтернативами. **Идеально** — source provenance для именно того ответа, если клиент его показывает (не исчерпывающий), но отсутствие такого UI provenance само по себе не опровергает Memory. Это **сильная наблюдательная атрибуция**, не экспериментальное доказательство. | Похожее на прошлое утверждение, общая continuity, повтор названия PR, самодиагноз «я вспомнила» без проверяемых источников. |
| **MEMORY POSSIBLE BUT UNPROVEN** | Есть **конкретный** старый уникальный detail + его повтор в ошибке либо правдоподобный stale-rule fingerprint, но нельзя исключить текущий чат/репозиторий/инструкции/генерацию; причинное влияние не продемонстрировано. Назвать **альтернативу** явно. | Просто любой класс G/E/O/V или факт, что пользователь много работал в проекте. |
| **NO EVIDENCE MEMORY CONTRIBUTED** | Ошибка документирована, но **нет специфического cross-chat fingerprint**; в текущем доступном задании/коде/тесте есть достаточная альтернативная возможность возникновения. Это значит **«не найдено положительного свидетельства»**, а не **«Memory точно не участвовала»**. | Молчание источников не доказывает, что retrieval отсутствовал. |
| **NOT ATTRIBUTABLE — ограничение наблюдаемости** | Нельзя восстановить точное содержимое *model-visible context*, прочитанные источники или порядок их доставки; одинаковый результат объясним несколькими каналами. Указать **недостающее свидетельство**, вместо притворной классификации как confirmed Memory cause. | Не превращать `NOT ATTRIBUTABLE` в «модель точно использовала старую память». |

**Два измерения оценки:** (1) есть ли **положительный специфический след Memory**; (2) достаточно ли данных, чтобы **атрибутировать источник**. «Possible» — наличие fingerprint с неустранённым альтернативным объяснением. «Not attributable» — недостаточная доступность происхождения; по одному кейсу можно записать и *potential candidate*, и итог `NOT ATTRIBUTABLE` без формальной причинной категории.

**Что отличало бы selection от weighting:**
- **Selection/content:** проверяемый **ложный/устаревший текст** из старого диалога появился в позднем ответе, не был нужен/верен сейчас.
- **Weighting/anchoring:** даже *правдивый* прошлый контекст модель предпочла более свежему и конкретному текущему поручению. Для Memory-версии нужен источник такого старого контекста, не сводимый к тексту текущего чата и GitHub.

Без установления канала retrieval это **поведенческие описания**, не отдельные подтверждённые причинные классы памяти.

Такое извлечение **не раскрывает model-visible retrieval в прошлом**.

### Контроль на ложную атрибуцию

Если эпизод можно причинно объяснить, просто читая **текущий** явно доступный текст или код, это **не доказывает отсутствие Memory**. Но чтобы предпочесть Memory конкурирующему объяснению, нужен **дополнительный специфический след**, которого в пяти кандидатах нет.

**Особенно не делать двух ошибочных выводов:**

1. «GPT-6 употребила прежний PR/head → извлекла его из Memory». Эта деталь могла уже быть в user-supplied previous-message quote, самом репозитории, project instructions или текущем чате.
2. «GPT-6 игнорировала новый `AGENTS.md` → Memory приоритизировала старый». Собственный план GPT-6, составленный **до** чтения текущего `AGENTS.md`, даёт другое объяснение без cross-chat retrieval.

## 5. Сила подтверждений, реальные ограничения доступа

- История чатов на нынешнем этапе доступна **выборочно**, без полного независимого snapshot пользовательского и системного context для **каждого** исторического GPT-6 ответа. Для кандидата B **не восстановлена полная prefix-последовательность** source of PR #215; для A нет logged moment memory retrieval, хотя есть признание последовательности план→прочтение.
- Публичные PR/commits доказывают существование файлов, текстов и runtime ошибок; они **не** показывают, какой именно **внутренний Memory snippet** и с каким приоритетом был передан GPT-6.
- Текущее memory-based персональное извлечение, которое мы явно запрашивали **сейчас для исследования**, не может задним числом подтвердить автоматическую Memory-подстановку **в прошлой** беседе.
- OpenAI Help предупреждает, что Sources не всегда перечисляют **каждый фактор** ответа. Поэтому даже отсутствие UI Memory attribution на конкретном старом сообщении не доказывало бы её невлияние.

**Установленный положительный факт уровня продукта:** cross-chat Memory **может** доставлять релевантный контекст и документы OpenAI признают риски stale/irrelevant памяти. **Установленный факт уровня наших ошибок:** на доступном историческом материале нет ни одного чистого случая, для которого `S → R → U → E` подтверждена наблюдаемыми свидетельствами.

**Осталось проверить при наличии уже существующих записей** — не тестами: был ли в одном из исторических вредных ответов конкретный, проверяемый **cross-chat-only** устаревший detail, и доступна ли тогдашняя запись источника (например, показанный пользователю Memory Source / полный текст текущего чата и tool reads). Пока ответа нет — **NOT ATTRIBUTABLE**, не гипотетический «виновник — Memory».

## 6. Handoff Sol / M1 conclusion

**Observational evidence hierarchy сформулирована; 5 конкретных кандидатов проверены; `MEMORY LIKELY CONTRIBUTED`: 0.**

**M1 итог:** `PLAUSIBLE MECHANISM, NO ATTRIBUTABLE GPT-6 FAILURE YET`.

**Никакого mitigation, правил Memory, управления настроек, новых файлов пользовательской памяти, тестов, A/B или workflow-контролей здесь не предлагается.** Исследование до следующей независимой проверки ограничено causal attribution.

**Вопрос Sol:** видишь ли ты в доступной истории хотя бы один **вредный** ответ, который перенёс *характерную устаревшую cross-chat-only деталь*, отсутствующую в текущем запросе/текущем чате/прочитанном PR, так что Memory становится **лучшим** объяснением? Если нет, прошу подтвердить честный отрицательный M1 и не превращать возможность stale-memory, признанную OpenAI, в доказанную причину наших ошибок.
