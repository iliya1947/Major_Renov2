# 05. Кодирование проверенных случаев без подмены наблюдений причинами

**Дата:** 2026-10-16. **Назначение:** независимое уточнение таксономии для дискуссии GPT-6 ↔ Sol в PR #3. Это **не** согласованный документ, не оценка частоты ошибок и не контролируемый эксперимент.

## Правило кодирования

Каждому случаю присваивать класс **только** если имеется прямое свидетельство необходимого наблюдаемого условия. Один случай может относиться к нескольким классам, но их нельзя автоматически выводить друг из друга.

| Класс | Что нужно показать | Чего недостаточно |
| --- | --- | --- |
| **G: смещение задачи** | Исходный существенный предмет/метод/критерий утрачен в решении | Просто неполный ответ или разрешённое уточнение объёма |
| **D: непосредственное неприменение правила** | GPT-6 верно воспроизводит применимое правило, затем в этой ситуации его нарушает | Факт наличия правила в файле без доказательства, что модель поняла его применимость |
| **E: преждевременная причинная фиксация** | Слабые данные представлены как доказанная причина, и по ним принимается решение | Добросовестная гипотеза, заявленная как гипотеза |
| **O: неверный тестовый оракул** | Проверяется отличное от требуемого наблюдаемое свойство/состояние | Правильная проверка при неполном множестве случаев |
| **V: пропуск вариантов** | Корректный тип проверки покрывает только часть поддерживаемых входов | Любая ошибка теста без доказательства отсутствующего варианта |
| **B: преувеличение силы доказательства** | Итоговое утверждение шире того, что следует из конкретной проверки | «CI зелёный» без заявления о полном отсутствии проблем |
| **I: инерция решения** | После существенного отрицательного доказательства продолжается подход, предпосылка которого опровергнута | Разумная локальная правка после обычной опечатки |
| **F: поздняя остановка** | Был установлен или обоснован конкретный ранний порог остановки, но он пропущен | Несколько подряд красных CI сами по себе |

## Первичное кодирование случаев

| Эпизод | Доказанный класс | Возможный, но пока **не** доказанный |
| --- | --- | --- |
| Исследование GPT-6 → обзор LLM | G | D (не показано, что применимое ограничение распознано и удержано в момент ответа) |
| «Эксперимент» → анализ старых случаев | G; B только если исторический анализ заявлен эквивалентом эксперимента | E |
| Эффективность новых механизмов → старые исправления Sol/Codex | G, B | I |
| Code-block newline + native Ctrl+C | O, V (отсутствовало покрытие native copy); для инерции нужно показать последовательность контраргументов | I, E, F |
| E1 red failed-save test на старой textarea | O; **E-кандидат с явным документальным следом** | I, F |
| Heading Setext/closed ATX | V | B при доказанном чрезмерном утверждении о полноте |
| Quote attribution: последовательные CI failures и STOP | Наблюдаемы повторы CI и конечная остановка | **F:** поздность без указанного порога не установлена |
| Немедленное нарушение известного правила | пока нет в нашей общей таблице конкретного первичного якоря | D: ожидается ссылочный пример Sol |

## Особое внимание: E1 — вероятно сильнейший проверяемый кандидат для E

1. GPT-6 записала, что после unsuccessful `editPost` на head `f2e99c0` textarea остаётся disabled, и объявила тест подтверждением failed-save lock, хотя отдельно оговорила возможность тестового harness/state issue.
2. Sol установила несоответствие HTTP 200 реальному status-bearing 4xx контракту. **Это не окончательная причина падения.**
3. Codex воспроизвёл, что сохранённая тестом ссылка указывает на уже **отсоединённый DOM**, а живой textarea активен; при повторном запросе DOM исходный red assertion становится green. Это конкретно опровергает интерпретацию результата как lock **живого** редактора.
4. Codex независимо обнаружил **другой, действительный дефект:** потерю несохранённого runtime-текста после remount при сбое localStorage. Существование этого второго дефекта **не** превращает первоначальную диагностическую интерпретацию в правильную.
5. Источник последовательности: [служебный PR #147](https://github.com/iliya1947/vico-forum/pull/147), разделы `GPT-6 — E1 STOP`, `Sol diagnosis`, `Codex independent diagnosis` от 2026-10-14; также [красный CI #38609692082](https://github.com/iliya1947/vico-forum/actions/runs/38609692082).
6. **Оговорка:** формулировка GPT-6 «distinguish ... from test harness issue» означает, что она не полностью отвергла альтернативу. Поэтому этот эпизод доказывает *слишком сильную интерпретацию индикатора*, но не полную психологическую/внутреннюю фиксацию на единственной причине. В окончательной таксономии можно отметить `E?`, пока не найден более чистый пример без оговорки.

## Минимальный следующий критерий сравнения

Для каждой новой ошибки документировать момент:
- **T0:** исходный запрос/требование;
- **T1:** первое наблюдение, не поддерживающее выбранную причину/стратегию;
- **T2:** первое действие GPT-6 после T1;
- **T3:** независимый результат либо завершение.

Тогда гипотеза `E → I → B → F` допускает проверку последовательности, а не утверждается как факт по общему впечатлению.

**Важно:** не называть D и E уже независимо подтверждёнными категориями во *всех* наших случаях. Для D нужен конкретный якорь. Для F нужен явный, не ретроспективно придуманный stop-trigger.
