# Part A — Diagnostic test accuracy questions

## 1. Diagnostic accuracy is not an intervention-effect PICO

### Established finding
**Confidence: HIGH**

A diagnostic test accuracy question asks how well an **index test** identifies or excludes a **target condition**, compared against a **reference standard**, in a defined participant population.

Core entities are therefore not simply:
- intervention;
- comparator;
- outcome.

The test itself is not an intervention in the ordinary causal-treatment sense.

Project consequence:
do not force DTA questions into intervention PICO.

---

## 2. Core DTA question elements

### Established finding
**Confidence: HIGH**

For diagnostic accuracy, the project should define at minimum:

1. **Participants / target population**
2. **Index test**
3. **Target condition**
4. **Reference standard**
5. **Intended role of the index test**
6. **Relevant threshold(s)** when test positivity depends on a cut-off
7. **Setting / pathway**, when it changes test performance or applicability

Cochrane DTA materials explicitly identify:
- index test;
- target condition;
- reference standard;
and current DTA review structure also asks for:
- participants;
- role of index test;
- prior tests / clinical pathway;
- alternative tests.

---

## 3. Index test

### Established finding
**Confidence: HIGH**

The index test is the test being evaluated.

It must be described sufficiently to identify:
- exact method/device/protocol;
- version if relevant;
- positivity threshold if relevant;
- interpretation method if subjective;
- operator/context if this can affect performance.

Project consequence:
“ultrasound”, “BIA”, “wearable”, “RIR estimate” can be too broad.

A device family and a specific measurement protocol may have materially different performance.

---

## 4. Target condition

### Established finding
**Confidence: HIGH**

Target condition = what the test is intended to detect/classify.

Examples conceptually:
- presence of disease;
- injury;
- clinically defined state;
- threshold state requiring action.

Exercise-project translation:
many of our future “measurement” questions are **not diagnostic**, because they do not classify a disease/condition.

Example:
“Does this tape protocol reliably measure arm circumference?” is a measurement-property question, not DTA.

---

## 5. Reference standard

### Established finding
**Confidence: HIGH**

Reference standard = best available method used to establish the target condition against which index-test results are compared.

Cochrane emphasizes:
- accuracy cannot be evaluated without some reference standard;
- reference standard itself may be imperfect;
- more than one acceptable reference standard can exist.

Project consequence:
do not casually call every comparator a “gold standard”.

Use:
- **reference standard**,
and document its own limitations.

---

## 6. Intended role matters

### Established finding
**Confidence: HIGH**

The same test can be used as:
- replacement;
- add-on;
- triage;
- screening;
- monitoring-related tool.

Accuracy alone does not fully determine usefulness.

Project rule:
DTA Question Card must specify intended role when it affects interpretation.

Example:
a fast low-cost test may be acceptable as triage while insufficient as definitive replacement.

---

## 7. Threshold is part of the question when classification depends on it

### Established finding
**Confidence: HIGH**

Sensitivity and specificity can change across thresholds.

Therefore:
“accuracy of test X” is incomplete when:
- threshold is variable;
- threshold was chosen post hoc;
- different studies use different cut-offs.

Project rule:
predefine:
- threshold(s);
or
- plan to model threshold variation.

Detailed DTA meta-analysis belongs to later methodology if needed.

# Part B — Measurement-property questions

## 8. Measurement question starts with the construct

### Established finding
**Confidence: HIGH**

COSMIN explicitly states that researchers should first define **what they want to measure** — the construct/outcome of interest — before selecting an instrument.

A label alone may be insufficient.

Example:
“strength” could mean:
- maximal dynamic strength;
- isometric force;
- grip strength;
- strength endurance.

Project consequence:
instrument choice follows construct definition, not vice versa.

---

## 9. Measurement instrument ≠ construct

### Established finding
**Confidence: HIGH**

A measurement instrument is **how** a construct is measured.

Examples:
- questionnaire;
- physical performance test;
- device;
- laboratory value;
- image-based score.

The construct is **what** is being measured.

Project rule:
never write:
> “DXA is the outcome”

when the actual outcome/construct might be:
- lean soft tissue;
- bone mineral content;
- body composition estimate.

---

## 10. Core measurement-review elements

### Established finding
**Confidence: HIGH**

COSMIN systematic-review methodology centers the question on:

1. **Construct / outcome domain**
2. **Population**
3. **Instrument or type of instrument**
4. **Measurement property/properties of interest**

Depending on use, also record:
5. context of use;
6. exact protocol/version;
7. feasibility/interpretability when selecting an instrument.

### Project framework

For measurement questions use:

**C-P-I-MP-U**

- **C** = Construct
- **P** = Population
- **I** = Instrument/protocol
- **MP** = Measurement property
- **U** = Intended use/context

This acronym is project-specific.

---

## 11. Measurement property must be named

### Established finding
**Confidence: HIGH**

“Is this measurement valid?” may still be too vague.

Possible properties include:
- reliability;
- measurement error;
- content validity;
- criterion validity;
- construct validity;
- responsiveness.

Different properties require different designs/analyses.

Project consequence:
Question Card must specify which property is being investigated.

Example:
> “How reliable is arm circumference?”
and
> “Does arm circumference validly reflect muscle hypertrophy?”
are different questions.

---

## 12. Population matters for measurement properties

### Established finding
**Confidence: HIGH**

COSMIN emphasizes that measurement properties are population-dependent.

A tool validated in:
- clinical patients;
- elite athletes;
- older adults
may not automatically have the same reliability/validity in:
- healthy home trainees.

Project rule:
population is mandatory in measurement-property questions unless strong reason supports broad generalization.

---

## 13. Intended use matters

### Established finding
**Confidence: HIGH**

A measurement can be adequate for:
- ranking people;
- group research;
but inadequate for:
- detecting small individual change.

Project consequence:
state intended use explicitly:

1. group comparison;
2. individual progress tracking;
3. screening/classification;
4. dose adjustment;
5. research endpoint.

This connects directly to later measurement-error/responsiveness analysis.

# Part C — Prognosis questions

## 14. Prognosis is not one question type

### Established finding
**Confidence: HIGH**

Current Cochrane Prognosis Handbook distinguishes at least:

1. **overall prognosis**
2. **prognostic factor**
3. **prediction model**

These answer different questions.

---

## 15. Overall prognosis

Question:
> What is the probability/distribution of a future outcome in a defined population over a defined time horizon?

Example adapted to exercise:
> Among detrained adults restarting resistance training, what proportion discontinue within 12 weeks?

This is not an intervention comparison unless a specific treatment contrast is introduced.

---

## 16. Prognostic-factor question

Question:
> Is a factor associated with future outcome, and by how much, in a defined population?

Example:
> Does baseline training history predict 12-week strength gain?

Critical warning:
prognostic association ≠ treatment-effect modification.

A factor can predict outcome across everyone without telling us which intervention is better for whom.

This distinction will later link to revalidation of individual-response methodology.

---

## 17. Prediction-model question

Question:
> How well does a multivariable model predict an individual’s future outcome?

Questions may concern:
- model development;
- validation;
- transportability;
- comparison.

This is different from asking whether one factor is causal.

Project rule:
do not interpret predictive variables automatically as causal mechanisms.

---

## 18. Current Cochrane prognosis framework = PICOTS

### Established finding
**Confidence: HIGH**

Current 2026 Cochrane Prognosis Handbook uses:

1. **P — Population**
2. **I — Index prognostic factor or prediction model**
3. **C — Comparator**, when relevant
4. **O — Outcome**
5. **T — Timing**
6. **S — Setting**

The meaning of **I** differs fundamentally from intervention PICO:
it means index prognostic factor/model, not treatment intervention.

Project consequence:
the acronym alone is insufficient; field definitions must be explicit.

---

## 19. Timing in prognosis has two parts

### Established finding
**Confidence: HIGH**

Cochrane prognosis PICOTS explicitly separates:

1. **startpoint** — moment from which prognosis is made;
2. **prediction horizon** — future time over which outcome is predicted.

Example:
- baseline = return to training;
- prediction horizon = 12 weeks.

Project rule:
prognosis questions must specify both.

---

## 20. Setting matters explicitly in prognosis

### Established finding
**Confidence: HIGH**

Current Cochrane PICOTS includes **S = Setting**.

For this project:
potential settings include:
- supervised laboratory;
- commercial gym;
- unsupervised home training;
- rehabilitation/clinical environment.

A predictor/model may not transport well across settings.

---

## 21. Predictor of outcome ≠ predictor of treatment effect

### Established finding
**Confidence: HIGH**

Cochrane prognosis resources distinguish ordinary prognostic factors from predictors of treatment effect.

Project rule:

### Prognostic factor
Predicts future outcome.

### Effect modifier / predictor of treatment effect
Predicts **difference in causal effect between interventions**.

Do not use a prognosis framework alone to justify personalized treatment choice.

---

# Part D — Framework-selection rules

## 22. Do not force every question into PICO

### Established finding
**Confidence: HIGH**

Project framework selection:

### Intervention effect
Use PICO/PICOT + estimand.

### Diagnostic accuracy
Use:
- Participants;
- Index test;
- Target condition;
- Reference standard;
- Role/threshold/setting as needed.

### Measurement property
Use project **C-P-I-MP-U**:
- Construct;
- Population;
- Instrument;
- Measurement Property;
- Use/context.

### Prognosis
Use current Cochrane **PICOTS**:
- Population;
- Index factor/model;
- Comparator;
- Outcome;
- Timing;
- Setting.

---

## 23. Same physical tool can generate different question types

Example: wearable heart-rate sensor.

### Diagnostic question
Can it classify tachyarrhythmia vs reference ECG?

### Measurement question
What is its agreement/error for HR versus ECG?

### Prognostic question
Does baseline wearable-derived HRV predict future training dropout?

### Intervention question
Does training guided by wearable HRV improve outcomes vs fixed programming?

These are not interchangeable and require different evidence/designs.

---

## 24. Practical rules produced by PASS-05A

1. Select framework from question type before searching.
2. Do not use intervention PICO as universal template.
3. Diagnostic accuracy requires:
   - participants;
   - index test;
   - target condition;
   - reference standard;
   - role/threshold where relevant.
4. Measurement questions begin with a precisely defined construct.
5. Separate construct from instrument.
6. Specify measurement property explicitly.
7. Record intended measurement use/context.
8. Prognosis questions distinguish:
   - overall prognosis;
   - prognostic factor;
   - prediction model.
9. Use current Cochrane prognosis PICOTS and define both startpoint and prediction horizon.
10. A prognostic factor is not automatically a treatment-effect modifier.
11. Same device/variable can appear in different question types; evidence cannot be transferred without checking the target question.
